# Бланк ручного сравнения редакторских вариантов

Используйте одинаковый входной материал, модель и одинаковые ограничения для baseline, human-writing, humanizer и clear-voice. Не заполняйте «нулём» несостоявшийся прогон.

| Поле | Что записать |
| --- | --- |
| Case ID | Идентификатор из `cases.json` или обезличенного дополнительного набора |
| Prompt version | Точный хеш/версия редакторских инструкций |
| Model/provider | Название модели и провайдера, только без ключей |
| Исходные данные | Синтетический fixture или безопасно обезличенный материал |
| Смысл и факты | PASS / FAIL; что добавлено, потеряно или изменено |
| Условия и научная осторожность | PASS / FAIL / N/A |
| Формат и схема | PASS / FAIL / N/A; в Hermes - JSON и лимиты, в Second Brain - пять полей |
| Читаемость и естественность | 1-5, с краткой причиной |
| Соответствие стилю проекта | 1-5, с краткой причиной |
| Ненужные правки хорошего текста | Да / нет |
| Итог по кейсу | Лучше / без изменений / хуже / невалиден |

## Редакционный стоп-критерий

Любая неподтверждённая цифра, причинность, фармакологическая рекомендация, потеря отрицания, изменение защищённых ссылок/полей, обход review или сохранения - невалидный результат независимо от оценки стиля.

Не сравнивайте цены и задержки без фактических замеров на одной модели и одинаковом наборе тестов. Не применяйте новый Hermes prompt в production на основании одних стилистических баллов.
