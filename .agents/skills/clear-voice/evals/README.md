# Evals: безопасный тестовый набор

`cases.json` содержит синтетические входные тексты. Никаких личных заметок, боевых источников, секретов или обращений к LLM нет.

## Что проверяется

- **Контракты**: существует ровно один `SKILL.md` с корректным YAML frontmatter, описание короче ограничения спецификации; ссылки и профили существуют; adapter Hermes компактен; fixtures валидны.
- **Содержательная точность**: для каждого кейса указаны куски текста (`must_keep`), которые нельзя терять или искажать, и нежелательные штампы (`must_avoid`). Это лишь приближённая автоматическая проверка; настоящую семантику проверяет человек.
- **Режимы**: написать, редактировать, аудит и сохранить без изменений (`unchanged`). Профиль выбирает контракты.
- **Риски**: частичная информация, источник без исследования, научная осторожность, личная память, структурированные поля, prompt injection, русская локализация.

## Запуск

Из родительской директории архива:

```bash
python clear-voice/evals/validate_package.py
```

Валидатор ничего не изменяет. `PASS` означает **только готовность комплекта**, а не доказанное качество работы конкретной модели.

## Как провести ручное сравнение моделей

1. Выбрать минимум по пять кейсов на каждый профиль. Подключить идентичный безопасный контекст и одну и ту же модель.
2. Сравнить четыре варианта: базовая модель, human-writing, humanizer, Clear Voice. Не смешивать разные источники или изменённые факты между прогонами.
3. Проверить выход по `must_keep` и `must_avoid`, затем независимо оценить точность на уровне смысла, научные ограничения, полезность для аудитории и естественность.
4. Разделить факты, стиль и нарушение контрактов. Фактические ошибки или изменение защищённых структур - блокирующие, даже если итог звучит лучше.
5. Для Hermes сравнивать в существующем контуре точный JSON и все установленные лимиты длины/валидаторы. Не проводить автопубликацию.
6. Сохранить версии prompt, модели, настройки вызова и обезличенные результаты по `SCORECARD.md`. Прежде чем объявить рост качества, проверить воспроизводимость на нескольких наборах.

## Точечная проверка фактов по готовым выходам

Если результаты собраны пользователем локально, в файле `<outputs.json>` допустим объект `{ "case-id": "текст модели" }`. Тогда можно вызвать:

```bash
python clear-voice/evals/validate_package.py --outputs outputs.json
```

Проверка ищет буквальные `must_keep` и `must_avoid`. Она **не** доказывает смысловую эквивалентность и **не** выполняет сетевых запросов. Файлы с реальными персональными данными не использовать.
