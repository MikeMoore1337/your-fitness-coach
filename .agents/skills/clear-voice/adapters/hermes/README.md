# Использование в Hermes: отдельный ручной этап

`EDITORIAL_STYLE_PROMPT.txt` предназначен для **добавления** в доверенную системную инструкцию конкретного редакционного LLM worker, а не для загрузки как отдельного агента. Это стилистические правила, не контракт вывода и не разрешение публикации.

## Как применить при отдельной задаче

1. Изучи актуальный `deploy/hermes-editorial-worker/editorial_worker.py`, `PROMPT_VERSION`, тесты и release/provenance документацию YFC. Уже существует слой `HUMAN_WRITING_EDITORIAL_RULES` после PR #922.
2. Сравни новую версию с текущим слоем на одинаковых безопасных fixtures. Не дублируй обе полные инструкции в системном сообщении.
3. Только после положительной проверки и отдельной задачи замени/обнови стиль в первичном и repair вызовах; не добавляй вызов модели, не меняй утверждённый provider, JSON-схему, три поля или source packet.
4. Обнови prompt version в соответствии с действующими контрактами, provenance, проверки initial/repair, source trust и тесты на сохранение фактов/чисел/медицинских оговорок.
5. Пройди требуемые CI и релизные этапы отдельно. Модерация и production deployment не входят в установку скилла.

## Чего не делать

- Не копировать весь `SKILL.md` в production prompt.
- Не добавлять внешнюю сеть, ключи или платные API.
- Не объявлять стилистическую LLM-оценку гарантией безопасности.
- Не отключать защитные валидаторы ради красивого текста.

Текущий пакет готов для ручного подключения, но **не подтверждает эффективность на реальных данных Hermes**.
