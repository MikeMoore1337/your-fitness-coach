# Установка и безопасная интеграция

## 1. Самостоятельный Agent Skill

Стандартная структура: папка с именем `clear-voice`, внутри `SKILL.md`. Профиль выбирается по задаче, а не по тому, в каком репозитории физически находится файл.

**Проектно (рекомендуется):** скопировать содержимое этого архива в `<repository>/.agents/skills/clear-voice/`. После копирования путь `<repository>/.agents/skills/clear-voice/SKILL.md` должен существовать.

**Для личного переиспользования:** разместить папку в каталоге навыков конкретного клиента (например, `~/.agents/skills/clear-voice/`, если ваша версия Codex его сканирует). Обнаружение и синхронизация зависит от версии клиента; проверьте список доступных скиллов после перезапуска/обновления сессии. Не устанавливайте один и тот же навык дважды без необходимости.

**Windows:** путь внутри репозитория, например `D:\Projects\your-fitness-coach\.agents\skills\clear-voice\`. Укажите ваш реальный путь, пример не требует администраторских прав.

**Другие агентные среды:** стандарт Agent Skills допускает тот же `SKILL.md`; используйте документированный конкретным клиентом каталог. Если у клиента нет механизма загрузки references, вручную подключите минимально нужный профиль.

## 2. В YFC

1. Проверьте актуальные `AGENTS.md`, `docs/skillspector-development.md` и текущую политику навыков. Репозиторий содержит `$evidence-content-editor`, `$technical-writer`, `$fitness-domain-reviewer`, `$localization-engineer` и другие роли; Clear Voice их не заменяет.
2. Добавьте `clear-voice/` в `.agents/skills/`. Для автоматического выбора достаточно короткой строки из `examples/AGENTS.snippet.md`; не копируйте полные профили в корневые инструкции.
3. Запустите локальный security gate репозитория и проверку внешних навыков по действующим правилам, затем обычные CI/PR Checks. Не обходите ошибки сканирования.
4. `SOURCE.json` для внешнего навыка YFC требует истинного immutable `source_commit`; **не заполняйте его выдуманным SHA**. Если навык позже будет размещён в собственном Git-репозитории и классифицирован как внешний, сформируйте манифест только из фактического URL, commit и лицензии по установленной схеме. До этого это вручную добавляемый собственный skill; правовой атрибут первоисточников уже есть в пакете.
5. Проверьте реальную редакционную задачу и при необходимости поправьте локальный словарь. Не вносите изменения UI/UX без согласования владельца.

## 3. В Second Brain

1. Размещайте папку скилла только в репозитории приложения, если так устроены его agent skills. **Не копируйте навык в приватный vault ради применения к заметкам**.
2. Вызовите профиль `second-brain`. Не меняйте контракт NoteDraft (`title`, `note_type`, `content`, `tags`, `links`), Safe Write, отдельное provenance и доступ к источникам.
3. При редактировании отобранных заметок предоставляйте только требуемый текст и синтетические тестовые примеры; личные данные не отправляйте внешним сервисам без одобрения.
4. После текстовой правки используйте существующий review, diff, dry-run и explicit apply. Сам skill не даёт права записывать файлы.

## 4. В Hermes

Codex Agent Skill сам по себе **не меняет** запросы runtime editorial worker. Компактная инструкция уже подготовлена в `adapters/hermes/EDITORIAL_STYLE_PROMPT.txt`.

В действующем YFC редакторский слой после PR #922 встроен в `editorial_worker.py`; его **не заменять автоматически**. Для замены нужен отдельный аудит текстов на одинаковых источниках, синхронизация prompt version/provenance и безопасная релизная процедура. Смотрите `adapters/hermes/README.md`.

## 5. В любом новом проекте

Скопируйте одну папку. Не редактируйте доменные профили других проектов: общий профиль `general` уже готов. Если требуется новый профиль, добавьте отдельный `profiles/<domain>.md`, но меняйте `SKILL.md` только для явной маршрутизации по этому домену.

## 6. Проверка и откат

1. `python clear-voice/evals/validate_package.py` - структура и синтетические fixtures.
2. Проверьте три реальных текста с редактором-человеком: короткий UI, длинный технический и научный материал; оцените не только стиль, но и сохранение смысла.
3. Чтобы отказаться от скилла, удалите только добавленную папку и локальную ссылку на него. Не откатывайте другие роли и редакционные контракты.
