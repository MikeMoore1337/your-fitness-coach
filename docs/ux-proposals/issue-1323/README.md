## Автономный интерактивный прототип

[Файл prototype.html](prototype.html) следует сохранить на компьютер и открыть в браузере; GitHub может показывать его как исходный код. Доступны переключатели Dark/Light и N=1/3/5/8/10/12/14, стрелки, горизонтальная нативная прокрутка scroll-snap, «Все дни», переход к последнему дню, выбор упражнений и демонстрационная мобильная панель / desktop правый столбец.

Параметры URL при локальном открытии: ?theme=dark&count=8&day=6&panel=1 или ?theme=light&count=14&day=14&all=1. Это только демонстрация компоновки: данные **не сохраняются**, API не вызывается, persist/dirty проверки в настоящем приложении не выполнялись.

## Контракт реализации после visual approval

1. **Одна модель формы.** Переиспользовать существующие React-состояния days, setDays/updateDay, текущую мутацию React Query, валидацию и dirty guard. Выбранные день и упражнение - отдельный UI state. Смена дня не сбрасывает черновик.
2. **Mobile 320/360/393/430.** Одна целая карточка дня на ширину видимой ленты. Нативный overflow-x и scroll-snap, без соседних видимых карточек и wrap-around; границы 1/N; для N=1 стрелки выключены. Вертикальные жесты по форме/списку не переключают день. iOS edge/back gesture и клавиатура не вызывают перескоков.
3. **Все дни.** Прямой выбор любого дня, полные названия и число упражнений; после выбора синхронизировать scroll, содержимое, индикатор, выделение и фокус. Нативная семантика/ARIA, клавиатура, >=44px цели, reduced motion, возврат фокуса после закрытия.
4. **Упражнения одного дня.** Строки с названием и подходы × повторы · отдых. Сохранить сложные повторы 12/10/8/15, заметки, суперсеты, замену, поиск, добавление, изменение порядка и вторичное удаление с подтверждением. Mobile - фокусированная панель со scroll/focus return; desktop - правый столбец.
5. **Сохранение.** Одна CTA с pending/success/error, без autosave. Закрытие/маршрутизация через существующую защиту грязной формы. При конфликте или ошибке сети черновик остаётся.
6. **Десктоп.** Дни слева / список выбранного дня по центру / параметры справа; общая бизнес-логика с mobile.
7. **Backend-граница.** До отдельного решения backend поддержка N=9..14 не заявляется. Это только дизайнерские контракты: API остаётся максимум 8 дней. Не изменять schedule_weekdays, повторения, назначение, migration, #916/#919/#920 в ходе UX-работы.
8. **Без регрессий.** Не изменять completed, revision/snapshot/assignment, #920/#967, не переписывать существующий поиск #1202. Общие дизайн-токены и компоненты YFC обязательны после согласования, новая карусельная библиотека не нужна.

## План тестирования реализации (не выполнен на текущем этапе)

- Unit: N=1/3/5/8, крайние дни, стрелки, переход «Все дни», изоляция данных дня, dirty-state, повторения/заметки/суперсеты/замены, сохранение и повторное открытие.
- Playwright: Chromium/WebKit, Dark/Light, 320/360/393/430, desktop 1440, касания/scroll-snap, отсутствие page overflow, вертикальные жесты, клавиатура, фокус и reduced-motion.
