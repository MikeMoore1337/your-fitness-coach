# Issue #951: два варианта массового выбора продуктов

**Статус: макеты для решения владельца.** Это изолированный интерактивный HTML-прототип: в нём нет API, базы данных и сохранения дневника. Названия, бренды, КБЖУ и порции в макетах синтетические. После принятия варианта нужны реализация, отдельная приёмка реальных AFTER-снимков и разрешение на доставку.

Основа: [dev `f0bc8567`](https://github.com/MikeMoore1337/your-fitness-coach/tree/f0bc85674f398ff7e1a41b3a8fbde060debfb77b), [Issue #951](https://github.com/MikeMoore1337/your-fitness-coach/issues/951), [решение владельца по #950](https://github.com/MikeMoore1337/your-fitness-coach/issues/950#issuecomment-6666591674) и [методика baseline](https://github.com/MikeMoore1337/your-fitness-coach/blob/f0bc85674f398ff7e1a41b3a8fbde060debfb77b/docs/development/product-v13-00-baseline-2026-11-05.md#L40).

## Выбор композиции

| | A — раскрывающаяся подборка | B — отдельная область подборки |
| --- | --- | --- |
| Поиск и выбор | Выбор в списке; подборка раскрывается над результатами. Запрос остаётся на месте. | Выбор в списке; на телефоне подборка открывается вкладкой, на desktop видна рядом. Запрос остаётся на месте. |
| Изменение количества | В раскрытой подборке; длинный список увеличивает прокрутку. | В отдельной вкладке или соседней колонке; на телефоне нужен переход к вкладке. |
| Стандартные порции, 1 / 3 / 6 продуктов | 4 / 8 / 14 действий в прототипе | 4 / 8 / 14 действий в прототипе |
| Сложность реализации | Ниже: одна основная область поиска и раскрываемый список. | Выше: синхронизация вкладок, двух колонок и фокуса при изменении ширины. |
| Основной риск | При большом числе продуктов редактирование вытесняет результаты вниз внутри прокручиваемой области. | Дополнительный переход к редактированию на телефоне; нужно сохранить доступность клавиатурной навигации и состояния при смене ширины. |

**Рекомендация: A.** Он сохраняет привычную структуру диалога, даёт быстрый выбор и позволяет открыть редактирование без смены контекста. B удобнее для одновременного обзора поиска и подборки на desktop, но добавляет переход на телефоне. В обоих вариантах нажатие на название показывает обычное одиночное добавление; отдельная кнопка выбирает продукт в подборку. Это предложение взаимодействия, а не подтверждение сохранения существующей реализации.

Оценка действий использует правило #950: каждый `click`, `fill` или `select` считается одним действием. Для шести продуктов: открыть диалог (1), шесть раз ввести полное название и выбрать результат (12), подтвердить (1). Использованы те же шесть синтетических названий и 100 г по умолчанию, что в #950. Редактирование порций и открытие подборки считаются отдельно. Baseline: один продукт — 4 действия; три в последовательном сценарии — 10; шесть — 19. В прототипе проверяется только демонстрационный итог, а не отправленные ID, сохранение или reload, поэтому это **оценка интерфейса**, не доказанное ускорение продукта. Время после реализации и пользовательский p95: **NO_DATA**.

## Что учесть при реализации

- [FoodPickerDialog](https://github.com/MikeMoore1337/your-fitness-coach/blob/f0bc85674f398ff7e1a41b3a8fbde060debfb77b/frontend/src/features/nutrition/FoodPickerDialog.tsx#L493) уже содержит recent/frequent/mine/favorites, поиск и существующее одиночное добавление. Текущий доступный label выбора включает только название: это недостаточно для одноимённых брендов.
- [Batch service](https://github.com/MikeMoore1337/your-fitness-coach/blob/f0bc85674f398ff7e1a41b3a8fbde060debfb77b/backend/fitminiapp_api/services/food_diary.py#L538) использует блокировку пользователя, fingerprint, ключ идемпотентности и общую транзакцию с rollback. `natural-input/commit` уже принимает несколько `food_id` с количеством и единицей. При реализации нужно проверить совместимость его семантики и аналитики с picker и повторить проверки на PostgreSQL; прототип ничего из этого не доказывает.
- [Текущая дедупликация результатов](https://github.com/MikeMoore1337/your-fitness-coach/blob/f0bc85674f398ff7e1a41b3a8fbde060debfb77b/backend/fitminiapp_api/services/food_catalog.py#L163) может скрыть внешний результат без штрихкода при совпадении нормализованных названия, бренда и близких КБЖУ, не сравнив разные идентификаторы провайдеров. Это риск для требования различать источники; нужны согласованный негативный набор и проверка всех затронутых вызовов.
- [Выбор внешнего продукта](https://github.com/MikeMoore1337/your-fitness-coach/blob/f0bc85674f398ff7e1a41b3a8fbde060debfb77b/frontend/src/features/nutrition/FoodPickerDialog.tsx#L550) сейчас выполняет отдельную запись в каталог до выбора количества. Это не запись в дневник; для новой подборки надо явно проверить её последствия, повтор и идентичность, сохраняя запрет неподтверждённых записей дневника.
- Неизвестные КБЖУ и клетчатка в прототипе показаны как «—». Единица и известный вес порции берутся из синтетических входных данных. Расчёты макета служат только демонстрации и не заменяют расчёты приложения.

## Проверки прототипа

- Playwright 1.62.1, Chromium 151.0.7922.34 и WebKit 26.5: сценарии 1/3/6 по методике подсчёта действий #950, раздельный выбор двух одноимённых брендов, редактирование и удаление без потери запроса, граммы/миллилитры/порции, отмена и повторное открытие, запрет неверного количества, неизвестные БЖУ и клетчатка. Это проверки синтетической страницы без записи в дневник.
- Скрипт проверяет отсутствие горизонтального переполнения и геометрию видимых controls на снимках; фактические результаты и границы описаны в Issue. Контраст нескольких использованных пар текста/фона проверен расчётом; полноценный аудит контраста и screen reader не проводился.
- Impeccable detector после коррекции контраста оставил два предупреждения: границы объединённого поля поиска и кнопки очистки соприкасаются, а Inter отмечен как распространённый шрифт. Второе противоречит закреплённой типографике YFC и не является основанием её менять. Предупреждения не равны полной проверке доступности.
- Оценка вариантов и проверка выполнены последовательно одним исполнителем; независимое ревью другим исполнителем не проводилось.
- PostgreSQL, конкурентные запросы, реальные сетевые ошибки, unit/API/production E2E, CI, физические устройства и production: **NOT_RUN**. Визуальное согласование, реализация, PR, merge и deploy: **не выполнялись**.
