приложенному референсу вариант A реализован в PR #1221; merge/deploy не выполнялись.

## Причина дефекта

Дефект воспроизводится на approved упражнении с 16:9 poster, например `incline-bench-press`, когда video/GIF недоступен или включён reduced motion.

1. `.active-workout-exercise__media` задаёт ширину, а дочерним `img` задаются `width: 100%`, `height: 100%`, `aspect-ratio: 1` и `object-fit: contain`.
2. При fallback через `<picture>` сам `.exercise-media-picture` не получает определённых квадратных `width` и `height`.
3. В результате intrinsic height 16:9 poster участвует в расчёте wrapper. В минимальном браузерном воспроизведении при ширине 280 CSS px получено: `picture/media ≈ 280×828`, внешний блок с рамкой `282×830`.
4. Прямой `<video>` при тех же правилах даёт `280×280`, поэтому проблема выглядит зависимой от ветки источника, хотя причина находится в геометрическом контракте wrapper.

Текущая CSS-геометрия thumbnails намеренно не входит в исправление: каталог и picker используют фиксированные поверхности 52/58 px.

## Варианты для владельца

### APPROVE A — квадратная поверхность с полным кадром

Задать квадратный контракт поверхности и квадратные размеры picture-wrapper. Внутренний GIF, poster или video остаётся `object-fit: contain` по центру. Для 16:9 появятся безопасные верхняя и нижняя matte-поля; тело, штанга, тренажёр и траектория не обрезаются.

### APPROVE B — квадратная поверхность с адаптивной привязкой

Сохранить тот же square + `contain`, но для широкого источника разрешить source-aware `object-position` внутри поверхности. Это меняет только положение полного кадра в matte-полях, не масштаб, не пропорции и не crop. Для квадратного GIF положение остаётся центрированным.

Оба варианта сохраняют текущую priority: MP4 → лицензированный GIF → poster/static → accessible missing state; reduced motion не создаёт video. Ни один вариант не заменяет исходный media, не запускает транскодирование и не использует AI-кадрирование.

Реальное сравнение Dark/Light для 320/360/393/430 px и кадры 0%/50%/последний доступны в
[изолированном HTML-прототипе](./visual-prototype.html). Реальные production AFTER для
guide/lightbox/Active Workout находятся в [evidence/after](./evidence/after/).

## Решение и ограничения

Owner direction: вариант A — квадратная поверхность с полным кадром и `contain`, без видимой
рамки. До отдельной visual acceptance разрешены только реализация одобренного scope, технические
проверки и подготовка AFTER; merge/deploy не входят в этот этап.

35 blocked упражнений остаются отдельными исключениями: отсутствие source не компенсируется crop, генерацией или неподтверждённым материалом. Инвентаризация проверяет metadata и целостность файлов; семантическая проверка техники по каждому кадру не выводится из одного SHA-256 и требует визуального review.
