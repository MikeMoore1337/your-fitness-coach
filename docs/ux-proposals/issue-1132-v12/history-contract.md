# #1132: предварительный контракт чтения фактического подхода

Статус: для разработки и проверки; API и тесты соответствия ещё не реализованы.

Для текущего подхода нужны два независимых значения. Предыдущий сегодня берётся только из фактически завершённого предыдущего подхода того же workout exercise; ожидающий локальный результат должен быть явно отличим от подтверждённого сервером. Факт прошлого выполнения берётся только из завершённой тренировки того же владельца, той же доказанной программной позиции и canonical identity. Номер, вид (`set_kind`), роль (`planned_role`), group/round/position и per-side семантика должны совпадать там, где они значимы. Неизвестная либо неоднозначная идентичность означает отсутствие соответствия, а не подбор соседнего результата.

Возвращать только actual_weight и actual_reps, дату/время источника и его идентификацию; не подставлять prescribed weight. Чтение не меняет данные и не становится evidence для автоматической прогрессии #917. Выбор последнего фактического выполнения не должен перескакивать к более старому при отсутствии нужного сета в последней подходящей тренировке. light/medium/heavy — справочный атрибут только при наличии доказанного snapshot.

Тестовые оракулы: 1–4 и произвольный номер; отсутствующий/незавершённый соответствующий сет; совпадение номера с отличной ролью/видом/группой/стороной; повтор позиции другого упражнения или дня; другая учётная запись; изменённая структура, null/legacy идентичность, незавершённая тренировка, reschedule, смена программы и 409/offline. Проверять отсутствие записи в историю, сохранение текущего результата и фактических значений. Реализация и security/API tests остаются NOT_RUN.

Текущий `build_exercise_history` фильтрует completed workout и пользователя, но объединяет по exercise ID и исключает сеты вне working volume; он не доказывает позицию и полную роль. Поэтому его recent_sessions нельзя использовать как соответствующий сет без новой проверки идентичности.
