Быстрый выбор проверенной замены

PROPOSAL · НЕ PRODUCTION

Вариант 02 · нижний лист — финальный пакет

Владелец выбрал нижний лист. Исправленная нижняя область всегда держит две кнопки в одной строке: Показать изменения слева и Отмена справа. Визуальная компоновка не меняет серверную проверку: сначала выбирается кандидат из полного ответа GET alternatives, затем отдельным шагом строится preview, и только после него доступен apply.

Данные прототипа Обезличенная синтетическая фикстура, повторяющая форму существующего ответа API. Поиск и фильтры действуют только внутри уже возвращённого полного множества.
01

Быстрый список

Три лучших результата сразу, полный ответ — по запросу.

Сильная сторона: самый короткий путь к частой замене. Риск: длинный полный список требует аккуратного фокуса.
02

Нижний лист

Короткий выбор наверху, поиск раскрывается в отдельном слое. Выбран владельцем.

Сильная сторона: спокойная иерархия на 360–430 px. Риск: дополнительный слой и возврат фокуса.
03

Сравнение

Исходное упражнение и выбранная замена видны рядом до preview.

Сильная сторона: меньше сомнений перед preview. Риск: больше вертикали и текста.

OWNER GATE

Что нужно утвердить

  1. Подтвердить исправленную строку: Показать изменения | Отмена, без переноса и смены порядка на 320–430 px.
  2. Подтвердить нейтральный текст допустимости: оборудование и факт серверного ответа показываются, технические reason_keys пользователю не выводятся.
  3. Подтвердить локальный поиск только по полному GET-ответу; при пагинации/лимите нужен отдельный API-контракт.
  4. После этой приёмки — отдельные implementation checks, реальные AFTER и второй owner visual acceptance.
