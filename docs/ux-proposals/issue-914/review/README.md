## Подтверждённая причина

1. `.active-workout-rest` в `frontend/src/styles/react.css` имеет `pointer-events: none`; только дочерняя группа действий возвращает `auto`. На 393 px касание на 3 px ниже кнопки +30, **внутри нарисованной панели**, проходит к кнопке «Готово» подхода 201. Получен PATCH `is_completed=false`, активный подход меняется 202 → 201. Воспроизведено touch input обоих движков. Это неправильный hit-testing поверхности, а не bubbling из обработчика таймера. [События и геометрия](audit/event-trace.json).
2. «Пропустить» немедленно размонтирует панель; второе быстрое касание по прежней координате попадает в предыдущий подход. Первый тап сам по себе не меняет подход; второй отправляет PATCH и делает 201 активным. [Отдельная трасса](audit/skip-event-trace.json).
3. Изолированная проверка `pointer-events: auto` на прежней панели, без перемещения и добавления отступов, удерживает касания на ASIDE: 202 остаётся активным, set-mutations нет, +30 продолжает работать. [Контрольный эксперимент](audit/isolated-hit-proof.json). Это проверка направления исправления; production CSS пока не изменён.

## Предлагаемая окончательная компоновка

- Компактная sticky-панель **в потоке тренировки**, перед упражнениями. Текущее поле с подписью остаётся достижимым ниже панели; высота около 109–110 px против текущих 107 px на телефоне. На tablet/desktop — одна строка около 64 px.
- Вверху оставшееся время Inter и следующий подход; ниже один ряд `+30 сек / +60 сек / Пропустить`. Все кнопки одинакового размера, ≥44×44 px, подписи в одну строку на 320/360/393/430. Необязательное −30 не добавлено.
- Существующий Liquid Glass material, тонирование 95%/96% как у согласованного плавающего меню, без новых слоёв/библиотек. Oswald/Inter и остальные поверхности B сохранены.
- Вся видимая поверхность принимает касания. При пропуске остаток обнуляется сразу; последний hit area сохраняется на 600 ms против повторного тапа, затем панель сокращается до спокойного статуса 44 px «Отдых пропущен». 600 ms взяты из существующей защиты повторного завершения подхода; финальную реализацию этой защиты нужно покрыть компонентными и E2E-тестами после approval.
- +30/+60 сохраняют выбранный подход, 42.5 кг / 9 повторов, позицию прокрутки и фокус поля. Клавиатура Tab/Shift+Tab/Enter работает; счётчик имеет `aria-live=off`, результаты действий озвучиваются отдельно. VoiceOver физически не проверен.

Background/resume: 1:54 → 0:49 через 65 сек; offline +60: 0:49 → 1:49; reconnect без set-mutations. Это текущий timer engine с изолированными preview-controls, не сквозная production-проверка финального #914. Reload/session recovery и полная совместная регрессия обязательны после реализации.

Клавиатура: модель viewport 480 px и Telegram events, сфокусированное поле **вместе с подписью явно приведено в центр**. Это подтверждает достижимость и компоновку; автоматическая прокрутка физического iOS не подтверждена. Headless WebKit не подтверждает оптический backdrop blur; читаемость поддерживается тонированием. Fallback/контраст финальной реализации и физическая калибровка ещё нужны.
