# #833: импорт истории тренировок

Статус: **макет ожидает утверждения владельца**. Основа — интерфейс истории из
`dev` на `106f75ab13ca6cc788817bdb7502352ce0dd3aba`.

Макет добавлен временной подменой DOM поверх работающего React с синтетическими ответами API.
Кнопки, данные и сообщения показывают предлагаемый интерфейс; они не загружают и не сохраняют
историю. Это не AFTER реализации и не доказательство работы API, базы или сохранения.

## Что предложено

- Вход из раздела «Прогресс → История» и загрузка CSV по нейтральному шаблону YFC.
- Предпросмотр тренировок и подходов до изменения истории; отдельные действия для неоднозначного
  и неизвестного упражнения. Ни один похожий вариант не выбран автоматически.
- Явная проверка возможного дубля, строки с ошибкой и неподдерживаемого разделения по сторонам.
  Исключения перечислены перед сохранением.
- Отдельное подтверждение, результат, проверка состояния после потери соединения и повторное
  открытие черновика до окончания срока хранения.

Экран неизвестного упражнения использует отдельный синтетический пример. Все имена, даты, значения
и срок действия на изображениях условные.

## Полный пакет

Каждая ссылка «состояния» показывает все 10 состояний по порядку: вход, загрузка, предпросмотр,
неоднозначное упражнение, неизвестное упражнение, дубли и ошибки, подтверждение, успех, ошибка
соединения и повторное открытие. Ссылки «контекст» показывают загрузку внутри исходного экрана.
Панели состояний сняты без перекрывающей их фиксированной нижней навигации; контекстные снимки
сохраняют навигацию.

## Проверка макета

Playwright: 20 сочетаний браузера, темы и размера. Проверялись горизонтальное переполнение панели
и заблокированное сохранение неоднозначного сопоставления без выбора. Снимки сделаны браузерами
Chromium и WebKit с подменённым тестовым API. PWA, реальный Telegram, физические устройства и
screen reader не проверены. Исходный тест и конфигурация: [prototype.spec.ts](prototype.spec.ts),
[prototype.config.ts](prototype.config.ts).

Утверждение этого макета разрешает реализацию согласованного интерфейса. Реальные AFTER и их
визуальная приёмка остаются отдельным этапом; принятие макета само по себе не подтверждает
проверку безопасности или работоспособность импорта.
