# Детерминированный импорт программ из XLSX/CSV

Task 93A реализует узкий импорт программ тренировок в личные шаблоны. В первой версии
принимается только канонический шаблон YFC v1. Произвольные выгрузки, эвристики, AI-
сопоставление и расширение до TXT/DOCX относятся к отдельному решению и в Task 93A не
включены.

## Канонический формат v1

Файл начинается со строки версии:

```text
#yfc_template_version,1
```

Вторая строка содержит фиксированные имена колонок. Поддерживаются следующие поля:

`program_title`, `goal`, `level`, `day_number`, `day_title`, `exercise_name`,
`prescribed_sets`, `prescribed_reps`, `rest_seconds`, `exercise_id`, `exercise_slug`,
`metric_type`, `prescribed_duration_minutes`, `notes`, `superset_group`, `superset_order`.

`program_title`, `goal`, `level`, `day_number`, `day_title`, `exercise_name`,
`prescribed_sets`, `prescribed_reps` и `rest_seconds` обязательны как колонки. Значения
`goal` и `level` должны быть едины для всей программы и соответствовать существующим
контрактам `ProgramTemplateCreate`. Каждый день имеет номер от 1 до 8, не более 20
упражнений, а суперсет состоит ровно из двух позиций.

CSV должен быть UTF-8 (BOM допустим) с разделителем-запятой. XLSX должен содержать ровно
один видимый лист, без формул, макросов, внешних ссылок, встроенных объектов, объединённых
ячеек и скрытых строк/колонок. Поддерживаются inline strings и обычные shared strings.
Шаблоны можно скачать из блока «Импорт программы»; они генерируются из того же контракта,
что и parser.

## Жизненный цикл

1. Пользователь загружает XLSX или CSV.
2. Сервер проверяет размер, ZIP/XML/CSV-структуру, лимиты и фиксированную схему, затем
   нормализует строки в короткоживущий draft.
3. UI показывает предпросмотр, ошибки, предупреждения, варианты сопоставления и координаты
   источника (лист/диапазон строки/ячейка); исходный файл не сохраняется.
4. Для отсутствующего или неоднозначного упражнения пользователь выбирает запись из
   доступного ему каталога. Автоматическое сопоставление использует только точные
   `exercise_id`, `exercise_slug`, title/alias и безопасную транслитерацию; fuzzy matching
   отсутствует. Если несколько идентификаторов строки противоречат друг другу, строка
   блокируется до ручного разрешения.
5. При подтверждении сервер повторно блокирует draft, пересобирает и валидирует его в
   одной транзакции, создаёт один редактируемый личный шаблон и не назначает его в активную
   программу. Повторное подтверждение того же draft возвращает тот же шаблон.
6. Отмена или истечение TTL удаляет нормализованный draft. Фоновый worker очищает истёкшие
   pending-drafts ограниченной пачкой; в audit остаются только безопасные счётчики и
   технические идентификаторы.

Все операции чтения, исправления, отмены и подтверждения проверяют владельца draft.
Исходные значения, заметки, имена файлов и содержимое ячеек не попадают в telemetry или
audit details.

## Ограничения и защита

Значения по умолчанию задаются в `Settings` и могут быть изменены конфигурацией окружения:

- файл — до 2 000 000 байт, request body — до 2 400 000 байт;
- не более 500 строк, 18 колонок, 8 000 ячеек и 512 символов в ячейке;
- XLSX — не более 32 ZIP-записей, 4 000 000 распакованных байт и коэффициента сжатия 100;
- parser должен завершиться за 5 секунд;
- draft доступен 60 минут, cleanup обрабатывает до 100 записей за проход.

Перед записью проверяются path traversal, duplicate ZIP entries, encrypted/symlink entries,
XML DTD/entity, formula cells и активный контент. CSV/XLSX экспортный шаблон также экранирует
значения, начинающиеся с формульных префиксов.

## Evidence и границы следующих задач

Регрессионные сценарии используют только синтетический versioned corpus, создаваемый в
`backend/tests/test_program_import.py`: round-trip обоих форматов, пропущенные ручные поля,
неизвестное/противоречивое упражнение, duplicate/empty rows, adversarial XLSX, owner
isolation, cancel/expiry и idempotent confirm. Reproducible benchmark запускается вместе с
этим тестом; baseline ручного переноса до реализации зафиксирован ровно как `not measured`.
Реального пользовательского corpus в текущем решении нет, поэтому его показатели не
выдумываются.

Task 93B не авторизована этим контрактом. Она может быть рассмотрена только после измерения
unsupported/manual-resolution gap на фактическом использовании 93A и отдельного решения по
privacy/cost/provider boundary.

Миграция `0076_program_imports` добавляет только owner-scoped таблицу короткоживущих draft;
существующие таблицы программ и назначений не меняются.
