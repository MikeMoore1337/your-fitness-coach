## OpenGym3D evidence: why not bulk-import it

[OpenGym3D](https://github.com/AssiamahS/opengym3d) at the inspected `main` has **42 exercise JSON specs**. Classification from the `mocap` and `status` fields:

| State | Specs | Production readiness |
| --- | ---: | --- |
| Public CC0 motion referenced | **7** | Source motion exists, but export, technical QA, anatomical visual quality and precise YFC correspondence are unverified |
| Local sample video-capture motion referenced | **2** | Authorship and use rights to the capture need independent verification |
| Private Mixamo FBX referenced | **16** | Missing publicly available original FBX; app rights and redistributed render rights need assessment |
| `draft` with no approved motion | **17** | Not render-ready |

The Git tree exposes two CC0 motion-pack GLBs, but **no ready-to-embed exercise-specific rendered GLBs**. The MPFB2 mesh and motion retargeting pipeline exist as code. **No Ab Wheel specification; Romanian Deadlift is a draft and Kettlebell Swing points to a private Mixamo source.** Hence OpenGym3D does not fill the three current pilot gaps today. Its MIT repository license is not a blanket grant for separately licensed motions.

See the upstream [asset policy](https://github.com/AssiamahS/opengym3d/blob/main/assets/ASSET_LIBRARY.json), [motion pipeline](https://github.com/AssiamahS/opengym3d/blob/main/docs/ASSET_PIPELINE.md) and [CC0 notice](https://github.com/AssiamahS/opengym3d/blob/main/motions/cc0/mesh2motion/LICENSE-CC0.md).
