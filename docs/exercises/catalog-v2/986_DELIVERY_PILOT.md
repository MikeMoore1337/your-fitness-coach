# #986: локальная HTTP-доставка видео и poster fallback

Статус: **RESEARCH_ONLY**. 2026-10-16. Дополнение к [986_TRANSCODE_RESEARCH.md](./986_TRANSCODE_RESEARCH.md) и Draft PR #1029.

## Что проверено

На том же **локальном игнорируемом** наборе четырёх упражнений (8 H.264 MP4 после кодирования 480p/720p) и соответствующих 480p WebP-постерах запущен `scripts/research_exercise_media_delivery.cjs`. Временный Node HTTP-сервер привязан только к `127.0.0.1`, раздаёт локальные материалы по белому списку имён, выставляет `video/mp4`, `image/webp`, `nosniff`, `no-store`, `Accept-Ranges` и поддерживает byte-range/206. Внешних запросов и публикации файлов нет.

Пилотная HTML-страница **не является частью YFC**, а моделирует *предлагаемый* контракт: WebP-постер показывается изначально; при `prefers-reduced-motion: reduce` видео не создаётся и сетевой запрос к нему отсутствует; при нормальном режиме видео загружается после пересечения viewport через `IntersectionObserver`, скрывая постер только после `loadeddata`; при ошибке остаётся постер. Проверки выполняются на Playwright Chromium и WebKit с DPR=2 и `colorScheme=dark`.

## Измеренный результат

**38/38 PASS** на Windows headless Playwright:

- По 8 клипов на каждый браузер: воспроизведение `currentTime >= 0.2` при ширине 390 px, наличие постера, успешный переход `loadeddata` и HTTP-запрос; отдельно режим reduce при 320 px, где HTTP-запросов к видео **0** (32 проверки).
- Дополнительные 320/430 px для первого клипа в обоих браузерах (4 проверки).
- HTTP 404 для видео в обоих браузерах, с сохранённым видимым постером (2 проверки).

Сырые результаты фиксируются в [986_DELIVERY_COMPAT.csv](./986_DELIVERY_COMPAT.csv). Поля `encoded_bytes` - локальный размер целого MP4; `video_requests` и `poster_requests` - количество запросов, зарегистрированных **на сервере**. Playwright `page.on('request')` в данном окружении не фиксировал часть фактически воспроизведённых WebKit-видео, поэтому метод подсчёта заменён на серверный. `loadeddata_ms` - локальная задержка от начала скрипта в браузере до события `loadeddata`, **не** измерение 3G/4G/5G, фактических байтов по сети, UX на телефоне или LCP. Сообщаемые WebKit `videoWidth/videoHeight` в этом окружении иногда соответствуют CSS-размеру, поэтому они не заменяют FFprobe/метаданные исходника.

## Воспроизведение

```powershell
# Из корня специального worktree; предварительно выполнены pinned SHA-verified transcode + poster benchmark.
node scripts/research_exercise_media_delivery.cjs
```

Входы находятся только в `.artifacts/tasks/986/pilot/transcoded/` и `.artifacts/tasks/986/pilot/poster-transcoded/`. Результаты нового прогона по умолчанию записываются **в ignored файл** `.artifacts/tasks/986/pilot/reproduced-delivery-compat.csv`, не перезаписывая зафиксированный CSV из Git. Отсутствие входов - ошибка, не повод скачивать замену из сети. Для точного воспроизведения исходных бинарников по хешам использовать подготовку из `986_TRANSCODE_RESEARCH.md`.

## Не пройденные production gates

Тестируется минимальный **исследовательский HTML-контракт**, не компонент `ExerciseGuideMedia` или `ExerciseMediaAsset`. Не измерялись физический iPhone/Safari, Telegram Mini App, реальные мобильная сеть/transfer, CPU/GPU/battery/RAM, accessibility в приложении, офлайн-кэш или визуальная корректность техники. Анализ прав на перепубликацию производных файлов остаётся отдельным от owner-confirmed права на использование источника в YFC. Не менять текущие 167 GIF и 39 blocked, манифест/API v3, продакшен или публичные бинарники на основании данного результата. Для продуктового внедрения по-прежнему нужны подтверждение прав на способ размещения и производные файлы, просмотр техники владельцем, реальные тесты на устройствах и отдельный visual/merge/release approval.
