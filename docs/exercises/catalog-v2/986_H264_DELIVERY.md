# #986: совместимый H.264 медиапилот для двух подтверждённых упражнений

**Статус:** реализация ограниченного объёма (barbell-curl и burpee), а не полное закрытие #986. Базовый релиз улучшенных 13 JPEG-постеров - PR #1045. Исследовательская база - объединённый PR #1029.

## Решение владельца

16 октября 2026 года владелец YFC подтвердил все права на любые способы использования, обработки, публикации и распространения медиа из `akajdid-mostafa/exercises-media` и производных в YFC. Дополнительное юридическое подтверждение не запрашивать. Пользователь согласовал перенос визуальной проверки техники и тестирования на физических iPhone и Telegram Mini App на **после контролируемого production release**. Не выдавать десктопный WebKit за физическое iOS.

## Новый контракт без поломки старого

- Оставляем `schema_version=3`, старое `type=animation`, `url`/перечень GIF `sources`, `poster` и карточки каталога неизменными для старых клиентов.
- Для **двух** точно сверенных `VERIFIED` упражнений только добавляем необязательный `video_sources` к guide API (для всех других упражнений пустой массив). Источник и выходные профили проверены по SHA-256, байтам и закреплённой ревизии.
- Превью карточек каталога не получают MP4 в `animation_url` (старые клиенты ожидают GIF). Новый веб-клиент в guide использует 854×480 H.264 CRF29 для миниатюры и 1280×720 CRF28 для увеличенного просмотра, `muted autoplay loop playsInline`.
- MP4 начинает загружаться лишь после приближения компонента к viewport через `IntersectionObserver`, постер отображается до готовности кадра. При ошибке видео возвращаем исходный GIF; ошибка GIF ведёт к уже существующему постеру. При `prefers-reduced-motion: reduce` видео **вообще не создаётся**.
- Клипы и постеры доступны только с origin YFC по `/static/exercise-guides/`, без внешних runtime API/CDN/платных сервисов. На уровне приложения не запрашивается микрофон/аудиодорожка.

## Проверенные профили

| Упражнение | 480p bytes | 720p bytes | GIF fallback |
| --- | ---: | ---: | ---: |
| `barbell-curl` | 80 755 | 140 896 | 106 020 |
| `burpee` | 109 332 | 200 132 | 100 254 |

Входные файлы взяты **только** из локальных FFmpeg-выходов, измеренных в `986_TRANSCODE_BENCH.csv`, сверены с `output_sha256` и байтами. `scripts/import_verified_exercise_video_pilot.py` по умолчанию выполняет dry-run и не скачивает файлы из сети. Для явного импорта требуется `--apply`.

## Ограничения и приёмка

- Существующие 165 анимаций вне этого пилота (и все 39 blocked) остаются в прежнем состоянии. Остальные `REVIEW/NO_MATCH` нельзя заменять похожими движениями автоматически.
- Настоящие iPhone Safari, Telegram WebView, реальные мобильная сеть/CPU/GPU/RAM и визуальная точность техники остаются на **пострелизную** приёмку владельца.
- До merge обязателен зелёный CI, validator, Python API tests, frontend types/lint/unit, MIME/Range/404-сценарии и отсутствие внешних runtime ассетов.
- Отказоустойчивость: старые GIF + новые JPEG-постеры находятся в том же манифесте; при клиентской ошибке MP4 используются fallback. Экстренный откат - revert коммита видеопилота и redeploy; пользовательские данные/БД не меняются.

Нельзя считать 1080px canvas исходника доказательством настоящей естественной HD детализации, а нормализованный SSIM - доказательством анатомической точности; визуальная приёмка остаётся реальной проверкой владельца.
