Снимок runtime-каталога YFC: `5041b77c8b29cfc4da26586154165aa734ffa6ef`; генератор запущен с HEAD `e6585c25e9351fa761fc987243a054a8fbba4175`. openGym: `7a3ace53c5e910c2185f22df803726c5838a99ae`. `summary.json` фиксирует SHA-256 байтов локального manifest и распределения источника. `source-review.csv.gz` хранит только ID, Git blob-хеши, заявленное происхождение и кандидатов; исходные тексты и медиа не копируются. Числовой ID GymVisual связывает медиа, но не доказывает семантическую идентичность упражнения. Точное нормализованное название или существующий alias тоже не дают права автоматически объединять записи.

Для связи **с YFC** все 6 554 строки — `REVIEW`: 172 кандидата требуют проверки идентичности, 2 имеют несколько кандидатов, 1 имеет конфликт имени и media ID, 922 являются upstream-вариантами без подтверждённой идентичности, 5 457 не имеют детерминированного кандидата. Отдельно 922 взаимные пары `variantOf` / `femaleVariant` классифицированы как `VARIANT` **внутри исходника**: его [описание полей](https://github.com/DuarteSantos8/openGym/blob/7a3ace53c5e910c2185f22df803726c5838a99ae/catalogue/README.md) определяет эту связь как изображение того же упражнения на женской фигуре. Это не доказывает связь с canonical YFC и не количество новых упражнений. Распределения мышц и оборудования относятся только к полям источника; `UNKNOWN` обозначает отсутствие поля, в том числе у ссылок вариантов.

`0592` и `0739` связаны с двумя canonical-кандидатами каждый; у `0603` кандидаты по имени и media ID расходятся. Проверка движения, оборудования и происхождения конкретного медиа не выполнена. Нельзя использовать эти связи как решение о дубликате.

## Воспроизведение

Нужны локальное окружение проекта и Git checkout openGym с каталогом `catalogue/exercises` на указанном SHA. Выходной каталог должен быть пустым. Команда не изменяет приложение или source каталог:

```powershell
.\.venv\Scripts\python.exe scripts\audit_830_catalog.py <путь-к-opengym> <путь-к-пустому-каталогу>
```

Скрипт проверяет revision и отсутствие изменений в source-каталоге, сверяет множество ID с Git tree, проверяет ссылки вариантов и совпадение множества canonical slug с manifest. Он формирует CSV и агрегаты. Поле `yfc_revision` отражает HEAD при запуске; SHA-256 manifest относится к фактическим байтам файла на платформе запуска. Для сравнения результатов используйте одинаковые байты manifest и содержимое source snapshot.
