# Impeccable: основной инструмент UX/UI-критики в YFC

**Источник:** https://github.com/pbakaus/impeccable, Apache-2.0. Зафиксированная версия 4.7.0, commit `dad8dbb3aac21ad1fa236c110315ef4abece23e8`; полный оригинальный набор находится в Git-подмодуле `.impeccable/` после инициализации. Этот проектный адаптер не копирует и не переписывает сторонний скилл.

## Подключение в рабочей копии

Из корня проекта один раз: `git submodule update --init -- .impeccable`. Проверь: `git -C .impeccable rev-parse HEAD` возвращает ровно `dad8dbb3aac21ad1fa236c110315ef4abece23e8`. Не использовать `--remote` и не обновлять источник автоматически. На Windows работает Git, административные права не требуются.

Открой Codex в **этой** рабочей папке и вызови `$impeccable` (либо «Применяй impeccable для UX/UI-аудита экрана X»). Канонический проектный вход - `.agents/skills/impeccable/SKILL.md`, он подгружает исходные инструкции из `.impeccable/.agents/skills/impeccable/`. Если подмодуль не загружен, не объявлять источник установленным и не выдумывать результаты его детектора.

## Повторяемый путь работы

1. **Контракт:** `AGENTS.md`, `codex-backlog/ACTIVE_DESIGN_SOURCE.md`, `.agents/references/DESIGN_GUARDRAILS.md`, `docs/design/YFC_PRODUCT_UI_CONTRACT.md`; задача и её явно согласованный визуальный режим. Обычная UX/UI-полировка - существующий дизайн, не новый.
2. **Критика до правки:** `impeccable critique` или `audit` - назвать route/state/viewport, реальные дефекты, тяжесть и контрпримеры; оценить типовой «нейрослоп» (случайные градиенты, одинаковые карточки, пустые отступы, иконки ради декора), но не объявлять запрещёнными Inter, Liquid Glass, фирменные цвета или осознанный motion.
3. **Предложение:** `shape` / `distill` / `layout` / `polish` по ситуации, не использовать `bolder`, `overdrive`, `colorize` без явно подходящей задачи. Покажи полноценный концепт и его связь с YFC.
4. **Owner gate:** для новой композиции - один согласованный пакет PNG/HTML, затем явное «Принимаю» **до реализации**; после реализации - реальные AFTER скриншоты, отдельное визуальное подтверждение и релизный gate. Точечные багфиксы - по существующим исключениям.
5. **Проверка:** действующие `$ui-audit`, `$accessibility-engineer`, Playwright Mobile/Web/TMA, 320/360/390/430, loading/empty/error, тёмная и светлая темы, safe area, клавиатура, reduced motion. Нет рендера - нет PASS. Не менять локализацию, данные или поведение ради эстетики.

## Границы исполнения

Используется **только в разработке**, не как React runtime или серверная зависимость. Не включать хуки, бинарники, `npx impeccable`, автоустановку, отправку скриншотов/исходников или автоматическую запись PRODUCT.md/DESIGN.md. Upstream launcher может загружать исполняемый файл при первом запуске: это требует отдельной проверки и явного выбора; для ручного чтения навыка он не нужен. Не использовать платные API. Смена дизайн-системы без разрешения владельца запрещена.

Из доступных альтернатив: `emilkowalski/skills` полезен для motion, `ibelick/ui-skills` - для технического качества, `ui-ux-pro-max` - для исследований. Они не заменяют первичную критику Impeccable и не запускаются автоматически.

**Проверка интеграции:** файл проекта и ссылка на исходный набор существуют, источник закреплён SHA, проектная маршрутизация срабатывает, а CI и права/визуальные gate не были ослаблены. Само наличие навыка не доказывает улучшения интерфейса.
