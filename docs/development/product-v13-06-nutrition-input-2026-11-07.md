# V13-06: текстовый и фото-ввод питания

Первоначальная база проверки: `origin/dev` `0a4d243de88ff62cea71fdb3768269c746a456db`; затем ветка синхронизирована с `06d09b06ba7164b096d3f7afec5a8f466ee96d8e`, где изменились только dev-updater и его тесты. Issue [#955](https://github.com/MikeMoore1337/your-fitness-coach/issues/955). Проверки используют синтетические данные; состояние production и его флаги не проверялись.

## Возможности и границы

| Возможность | Текущий контракт | Ограничение |
| --- | --- | --- |
| Текст | Серверный deterministic preview показывает строки и варианты, затем клиент отправляет выбранные позиции с явной единицей и ключом идемпотентности. | Preview не создаёт серверный черновик и не привязывает commit к исходному тексту. Неизвестные строки требуют выбора или явного исключения в интерфейсе. |
| Фото блюда | Доступны загрузка, черновик с кандидатами, редактирование, confirm и cancel. Ответ содержит `source_photo_retained=false`; исходное фото не сохраняется в модели черновика. | Provider получает нормализованное изображение при включённом адаптере. Фото-оценки и качество распознавания на реальной выборке — `NO_DATA`. |
| Этикетка | Есть отдельный OCR-путь и опциональный Vision fallback с собственными проверками и ручной проверкой результата. | Доступность и качество в production — `NOT_VERIFIED`; локальный OCR и внешний Vision не равнозначны. |

Значения исходного кода по умолчанию: scan и Vision выключены, оба kill switch выключены, Vision provider — `disabled`. Сервер разрешает scan при включённом флаге без kill switch; фото использует тот же guard. Для Groq-адаптера дополнительно нужны включённый Vision, провайдер, ключ, `zdr_verified` и разрешение preview-модели. Это не подтверждает настройки production. Ручной ввод не зависит от Vision.

Вход изображения проверяет MIME, сигнатуру, размер, число пикселей и минимальные размеры; EXIF удаляется при нормализации. Ограничение изображения по умолчанию — 8 388 608 байт, но `/photo-meals` сейчас попадает под общий лимит HTTP-тела 1 048 576 байт, включая multipart. Интерфейс допускает файл до 8 388 608 байт. Это расхождение остаётся зависимостью: изменение общего security gate не входит в этот scope. Проверка размеров не доказывает распознавание размытого или плохо освещённого снимка.

Черновик принадлежит пользователю и при первом обращении после TTL становится `expired`; TTL по умолчанию — 15 минут. Автоматическое физическое удаление содержимого по TTL здесь не доказано. При удалении аккаунта черновик удаляется. Значения и результаты provider не являются доказательством приватности внешнего сервиса в production.

## Изменения и локальное доказательство

- Фрагменты без количества больше не исчезают и остаются отдельными строками. Десятичная запятая сохраняется. Отсутствующая единица не превращается в граммы; API commit требует её явно.
- При нескольких точных совпадениях личный продукт больше не выбирается автоматически вместо общего; при усечённой выдаче поиска требуется ручной выбор. Явно сохранённый пользователем алиас остаётся отдельным выбором.
- Фото-confirm отклоняет список, в котором отсутствует кандидат из черновика. При замене файла клиент использует новый ключ запроса и игнорирует запоздавший ответ по предыдущему фото; повтор того же запроса сохраняет ключ.

Один и тот же синтетический набор из шести запросов выполнен через локальный API на SQLite:

| Наблюдение | До | После |
| --- | ---: | ---: |
| Выведенные строки из 9 ожидаемых | 7 | 9 |
| Корректно разрешённые строки | 4 | 5 |
| Неразрешённые отображённые строки | 2 | 4 |
| Ошибочное разрешение без единицы | 1 | 0 |
| Отклонённые commit без единицы из одного запроса | 0 | 1 |
| Распознанные повторы из одного повтора | 1 | 1 |

До исправления одна позиция отсутствовала, а ещё две были объединены в одну неразрешённую строку. Это счётчики только данного набора, не метрика качества каталога или production. Адресные проверки включают неполные БЖУ, неоднозначное совпадение, ограничение поиска, неизвестный соус, отсутствие калорий, чужой draft, TTL, отмену, повтор, ошибки провайдера и некорректные изображения. Fake Vision возвращает заранее подготовленные данные и не проверяет качество модели.

## Открытые зависимости и блокировки

1. **Фото-confirm не атомарен.** `create_food_diary_entry` внутри общего `services/food_diary.py` делает commit до сохранения статуса и snapshot черновика. На локальном PostgreSQL 16 при искусственном прерывании после этого commit наблюдались одна запись дневника, `draft` и пустой snapshot. При синхронизированном конкурентном confirm оба ответа были `201`/`replayed=false`, хотя запись была одна. В той же записи наблюдался `weight_g=1.000` при неизвестной массе. Требуется отдельная согласованная правка общего сервиса и повторные PostgreSQL regression tests; здесь общий файл не менялся. Последовательный повтор уже закрытого draft возвращает конфликт, поэтому восстановление после потери ответа также не доказано.
2. Повтор создания draft с тем же ключом возвращает существующий draft без проверки, что загружен тот же файл. Клиентский путь замены файла исправлен; серверное связывание payload требует отдельного решения о хранении производного от изображения идентификатора и privacy review.
3. Подтверждение фото остаётся технически незавершённым до решения пунктов выше; новый контракт удаления сохранённых данных или интерфейс не вводился.
4. **Внешний Vision: `BLOCKED_PROVIDER`.** На 7 ноября 2026 года пригодный для этого проекта провайдер, выполняющий одновременно требования постоянной бесплатности, отсутствия карты, допустимой обработки и retention и доказанного production-качества, не подтверждён. Это не утверждение, что такого решения не существует.

Для проверки provider gate использованы официальные источники: [Groq model card](https://console.groq.com/docs/model/qwen/qwen3.8-27b) обозначает используемую модель как preview и публикует платные тарифы; [Groq data controls](https://console.groq.com/docs/your-data) описывает ZDR и исключения хранения, но не подтверждает настройки или правовую пригодность конкретного аккаунта. [Gemini API terms](https://ai.google.dev/gemini-api/terms) описывают использование данных бесплатного сервиса для улучшения продуктов с региональными исключениями. [Hugging Face pricing](https://huggingface.co/docs/inference-providers/en/pricing) описывает ограниченные кредиты и платную дальнейшую обработку. Эти сведения нужно перепроверить перед любым решением; тестов с внешним ключом и реальными фото не проводилось.

Отдельные owner/provider/privacy и release gates сохраняются. `env change required: no` для этого изменения; никаких флагов или секретов не меняли.
