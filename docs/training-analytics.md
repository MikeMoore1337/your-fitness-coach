# Детерминированная аналитика тренировок

Расширенный API аналитики возвращает фактическую историю выполненных подходов. Он не рассчитывает
восстановление, усталость, готовность, «эффективные подходы», предполагаемый одноповторный максимум
или расход калорий.

- `GET /api/v1/workouts/progress/training-analytics?period_days=30&exercise_history_limit=20`
  возвращает аналитику авторизованного аккаунта.
- `GET /api/v1/coach/clients/{client_id}/training-analytics` возвращает те же данные, только если
  у авторизованного тренера есть активная связь с этим клиентом.

`period_days` принимает только `7`, `30` или `90`. Ограничение `exercise_history_limit` применяется
к каждому упражнению отдельно на уровне запроса к базе данных и принимает значения `1..100`.
Эндпоинты списка клиентов тренера остаются сводными и не загружают эту историю.

Ответ содержит границы предыдущего эквивалентного периода и `muscle_group_workload`. Для каждой
мышечной группы доступны текущие и предыдущие факты, изменение числа подходов, изменение частоты
и раскрываемые упражнения с ограниченной историей сессий. Если в одном из периодов нет
сопоставимых данных, соответствующий период равен `null`, а тренд — `no_comparable_data`.

Ответ также содержит `data_sufficiency` для полноты журнала тренировок, числа рабочих подходов и
покрытия необязательного RIR. Версия, статусы, причины и продуктовые пороги описаны в
[`data-sufficiency.md`](data-sufficiency.md).

## Формулы и отсутствующие данные

Границы периода рассчитываются в IANA-часовом поясе аккаунта и включают обе крайние даты.
Учитываются только рабочие подходы и дроп-сеты с `is_completed = true` в тренировках со статусом
`completed`. Разминочные подходы, запланированные, начатые, пропущенные и отменённые тренировки,
а также незавершённые подходы не входят в рабочий объём, прогрессию, RIR и нагрузку на мышцы.
Устаревшие записи с `set_kind = null` продолжают учитываться, чтобы миграция не меняла смысл
исторических данных.

| Показатель | Формула и единица | Отсутствующие данные и ограничения |
| --- | --- | --- |
| Выполненные подходы | Число учтённых рабочих подходов, дроп-сетов и устаревших строк без вида, подходы | Разминка исключена. Дроп-сет сохраняет отдельный `set_kind` и не превращается в оценку «эффективных подходов». |
| Повторы | Сумма записанных `actual_reps`, повторы | `reps_recorded_sets` показывает полноту данных. Если повторов нет ни в одном подходе, результат равен `null`; при неполных данных сумма может быть частичной. Повторы с разной нагрузкой не объединяются в оценку. |
| Максимальная внешняя нагрузка | Максимальный записанный `actual_weight`, кг | При отсутствии веса возвращается `null`. Это наблюдаемый вес, а не расчётный 1ПМ и сам по себе не доказательство роста силы. |
| Объём внешней нагрузки подхода | `actual_reps × actual_weight`, кг | Если нет одного из значений, возвращается `null`. |
| Объём внешней нагрузки тренировки или периода | Сумма вычислимых объёмов подходов, кг | `volume_recorded_sets` показывает полноту данных. Если вычислить нельзя ни один подход, результат равен `null`; при неполных данных сумма может быть частичной. |
| Лучший объём подхода | Максимальный вычислимый объём подхода, кг | Сравнивается только произведение записанных повторов и внешней нагрузки; это не показатель эффективных повторов или усилия. |
| Выполненная сессия | Появление упражнения в тренировке хотя бы с одним учтённым подходом | Дата берётся из `scheduled_date`, ограниченная история идёт от новых записей к старым. `performed_session_count` содержит полное число за период, а `history_truncated` сообщает об исключённых из ответа сессиях. |
| Распределение RIR | Число значений категорий `0`, `1`, `2`, `3`, `4+`, подходы | Отсутствующий RIR остаётся отсутствующим и учитывается отдельно. `4+` — категория, а не ровно четыре. Из RIR не рассчитываются усталость, готовность, восстановление или прогноз отказа. |
| Нагрузка на основные мышцы | Для каждой структурированной основной связи прибавляется число учтённых подходов упражнения, подходы | Долевой коэффициент не применяется. Один подход может учитываться для каждой явно связанной мышцы. Упражнения без структурированных метаданных показываются отдельно. |
| Нагрузка на вторичные мышцы | Тот же расчёт для структурированных вторичных связей, отдельно от основных, подходы | Основные и вторичные мышцы нельзя складывать в показатель «эффективных подходов». Метрика описывает связь в каталоге, а не измеренный стимул мышцы. |
| Частота мышечной группы | Число разных завершённых тренировок, в которых есть хотя бы один учтённый подход упражнения, связанного с группой; `сессии × 7 / дни периода`, раз в неделю | Одна тренировка с несколькими упражнениями для группы считается один раз. Частота не означает восстановление или оптимальность. |
| Сравнение периода | Предыдущий диапазон равной длины непосредственно перед текущим: `[current_start - period_days, current_start - 1]` | Сравнение и изменение не строятся, если в одном из диапазонов нет фактов. |

`uses_bodyweight_equipment` определяется по структурированной связи с оборудованием. Сохранённый
вес считается только внешней нагрузкой. Масса тела автоматически не добавляется, помощь в
упражнении не нормализуется и не вычитается. Поэтому подходы с собственным весом без внешнего
отягощения обычно имеют объём `null`, а упражнения с собственным весом или помощью нельзя
сравнивать по этому объёму как по полной механической работе.

## Запросы и конфиденциальность

Сервис выполняет запрос счётчиков достаточности, сгруппированные запросы текущего периода и
сессий текущего/предыдущего периода, запрос завершённых тренировок предыдущего периода, оконный
запрос ограниченной истории и запрос метаданных для фактически встречающихся упражнений. Число
запросов не растёт вместе с числом упражнений или сессий. Путь доступа покрывают существующие индексы пользовательских
программ, `(user_program_id, scheduled_date, status)`, упражнений и подходов тренировки и
структурированных связей упражнений; новая миграция не требуется.

ID пользователя всегда берётся из авторизованного серверного контекста. Для тренера повторно
используется существующая проверка активной связи; для посторонней или завершённой связи
возвращается `404`. Ответ содержит только агрегаты тренировок и ограниченную историю выполненных
подходов. Данные о питании, комментарии тренера и записи другого аккаунта не раскрываются.
