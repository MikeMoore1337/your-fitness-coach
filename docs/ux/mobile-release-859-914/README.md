# YFC · финальная интеграция #859 / #867 / #914

Реальные снимки работающей сборки приложения в Linux исходного дерева `7f78f0d7a28e9db0688fe763556b28ce9ba411a6`. Chromium и WebKit; API-данные синтетические, production-пользователи и их данные не использованы. [PR #927](https://github.com/MikeMoore1337/your-fitness-coach/pull/927), [Checks](https://github.com/MikeMoore1337/your-fitness-coach/pull/927/checks), [галерея](index.html), [диагностика](audit/tests.json), [manifest](manifest.json).

Пять пунктов общей панели: Сегодня / План / Питание / Прогресс / Добавить. Последний пункт — действие без постоянного активного состояния. Использован существующий glyph `plus`, 24 px; внешнего мобильного круга и места под него нет. Dock получил матовый Liquid Glass по принципу реальной панели таймера отдыха: Dark 95%, Light 96%, blur 20px, saturation 112%, без второго backdrop-filter. Desktop, Coach OS и специальные Demo-сценарии сохраняют свою семантику. Существующее меню быстрого добавления, glass-токены, Oswald/Inter, маршруты и данные сохранены.

BEFORE — предшествующая локальная production-сборка `4a4d2e5540fac5545645b3ad94fd000096a57f4e`: пять пунктов, прежние радиус и чрезмерно прозрачная плотность стекла. Снимки навигации — Linux; детерминированный P1 BEFORE повторно снят в Windows и явно помечен `da5cfa89ebcb400bb7f0043cf6fd471d4fe2a353`. Более раннее подтверждённое перекрытие #867 сохранено в [предыдущем пакете](https://github.com/MikeMoore1337/your-fitness-coach/tree/7c1995b05d2308c8521108782c4e2f69261cf3a0/docs/ux/issue-914-acceptance). Сравнения составлены из настоящих снимков без ретуши содержимого приложения; крупные планы — кадрирование.

P1 воспроизведён детерминированно в обоих движках: удержан ответ PATCH автосохранения, завершение ждёт существующий cross-context lock, но прежний обработчик уже отправляет `fit:rest`. В этот момент таймер = 1, серверный `is_completed=false`, текущий подход = 201. Это доказывает преждевременный запуск отдыха, а не постоянную потерю записи на сервере. [Сетевое доказательство BEFORE](audit/p1-before.json), [разбор и исправление](audit/p1.md).

Исправление: `enqueue` возвращает результат принятия; онлайн завершающий обработчик ждёт синхронизацию, офлайн — успешную долговременную локальную запись. Только после принятия запускаются подтверждение и отдых. Состояние завершения берётся из очереди/QueryCache. In-flight guard блокирует повтор и редактирование незавершённой операции; native double-click не превращается в undo. При отказе API доступен явный повтор сохранения; при отказе локального хранилища офлайн подход не меняется и ложного таймера нет. Таймер сохраняет deadline до события, включая переход на другой экран во время PATCH.

Таймер: +30/+60/Пропустить; реальные pointer/touch-события по центру и границам, повторные касания, отсутствие PATCH `is_completed=false` и перехода 202 → 201. Подход 202, 42.5 кг, 9 повторов, RIR 2 сохраняются. Добавлено открытие/закрытие меню и переход Питание → Сегодня → продолжение тренировки без workout mutations. Диагностика содержит геометрию, hit-testing, исходную/прокрученную позицию, фон/resume, offline/reconnect, модель safe-area и клавиатуры. Визуальные кадры отражают разные явно названные положения прокрутки; доступность рабочих полей проверена отдельно от возможности Playwright автоматически прокрутить элемент.

Адресная регрессия: 208 успешных сценариев; итоговый P1 stress: 256 прогонов (по 8 повторений); failures/flaky = 0, retries = 0. Mobile goldens, catalog и основной matte ancillary прошли. Ancillary Pulse содержит сохранённый pre-existing WebKit performance finding: 23/24 в полном прогоне и 3/3 в отдельном rerun снова превысили неизменный p95 frame-gap 34 ms (59/91/47/69 ms); это не путь dock/rest timer и не изменённый этой задачей runtime, поэтому классифицировано как `PRE_EXISTING_PERFORMANCE_FAILURE_OUTSIDE_SCOPE` в [статусе ancillary](audit/ancillary-status.json), а не скрыто. Прежний P1 прогон дал 239/240: один WebKit-сценарий отправил RIR null, видимого выделения «2» на видео нет; точная причина того единичного случая не установлена. Он не скрыт: [история диагностики](audit/p1-stress-history.json). Последующие 40 и 200 WebKit-повторов записали реальные события и сохранили RIR; итоговый тест дополнительно проверяет фактический выбор до завершения, без sleep и повторного касания. Локально 829 Vitest-тестов в 145 файлах; typecheck, lint, формат и сборка проверены. Backend: 4 теста offline workout sync, включая version conflict, idempotent replay и реальное повторное чтение из изолированной БД. Обязательный CI актуального PR HEAD записан отдельно в итоговом комментарии PR; этот пакет не доказывает deployment.
