# Issue #1292: макет компактной панели отдыха

**Ожидает согласования владельца.** Это предложение компоновки, а не реализация и не финальные
AFTER-скриншоты. Основа: `origin/dev` на `145ce620755463a1f294e86369fff6e854392168`.
В тренировке и запросах использованы синтетические данные. Личные снимки владельца не публикуются.

## Предложение

- На мобильной ширине статус расположен над группой действий. «Начать отдых» — основная кнопка;
  «Скрыть» — вторичная. Обе кнопки используют существующую визуальную систему YFC.
- На широкой панели статус и группа действий находятся в одной строке. Если повторный запуск
  недоступен, статус и «Скрыть» стоят рядом; после скрытия статуса остаётся доступный повторный
  запуск, если он предусмотрен текущей логикой.
- Длинные статусы и фактическое время не обрезаются. Активный и свёрнутый таймеры, закрепление,
  логика интервалов и история отдыха не входят в предлагаемое изменение.

## Что проверено

Для состояния «Отдых не учитывается» с двумя действиями выполнены 20/20 проверок браузерного
макета: Chromium и WebKit × Light и Dark × 320/360/393/430/1440 CSS px. Проверены отсутствие
горизонтального переполнения документа, расположение статуса и кнопок без пересечения, границы
кнопок внутри панели и размеры кнопок не меньше 44 × 44 CSS px. [Измерения](geometry.json).

В этом синтетическом сценарии высота панели в CSS-пикселях:

| Ширина viewport | Текущий dev | Макет |
| --------------- | ----------: | ----: |
| 320             |          86 |    86 |
| 360/393/430     |         114 |    86 |
| 1440            |          62 |    62 |

Это не проверка новой реализации, API, истории, повторных нажатий, реальной клавиатуры,
VoiceOver, Safari/PWA/TMA или физического iPhone. Их нужно проверить после реализации.

## Решение владельца

Согласовать весь показанный вариант: мобильную и desktop-компоновку, иерархию кнопок и состояния
с фактом, длинным текстом, одним действием и сообщениями сохранения. Согласование разрешает
реализовать только этот вариант. Реальные AFTER, их визуальная приёмка и разрешение на merge
остаются отдельными этапами.
