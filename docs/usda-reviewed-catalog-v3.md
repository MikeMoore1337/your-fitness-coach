# USDA FoodData Central: расширение проверенного каталога v3

Связано с [#938](https://github.com/MikeMoore1337/your-fitness-coach/issues/938),
первичной интеграцией [#934](https://github.com/MikeMoore1337/your-fitness-coach/pull/934)
и первым импортом [#935](https://github.com/MikeMoore1337/your-fitness-coach/pull/935).

## Что обновлено

- В исходном наборе `USDA_RU_DISPLAY_NAMES_V2` неизменны **118 FDC ID**.
- Версия `USDA_RU_DISPLAY_VERSION_V3 = fdc-fndds-2021-2023-ru-v3` расширяет
  тот же источник `usda-fdc-reviewed-ru` дополнительными **97** вручную
  проверенными FDC ID из `Survey (FNDDS)` 2021-2023. Всего **215**.
- Для каждого нового идентификатора проверяется **точное исходное название**
  `description` и `dataType = Survey (FNDDS)`. Сомнительный или изменившийся
  ID не переносится под ошибочным русским названием. Без машинных переводов.
- Сохраняются отличия сырых/готовых продуктов, масла, кожи, консервации,
  вида крупы/орехов/рыбы. `Blueberries` переводится как **голубика**,
  а не черника; неизвестный вид перца не попадает в выдачу «сладкий перец».
- Метаданные лицензии **USDA CC0-1.0** и происхождения не меняются.
  Отсутствующая клетчатка не приравнивается к нулю.
- Старые продукты не удаляются; поиск по русским словам дополняется точными
  группами и синонимами, без разворачивания узкого запроса на соседний продукт.

## Качество и метрики

Обязательные условия для одобрения новой партии:

1. Все 97 FDC ID должны существовать у официального USDA с точным
   `description` / `dataType`, достоверными КБЖУ и единицами на 100 г.
2. Пересечения с исходными 118 идентификаторами равны нулю.
3. Предыдущие 118 строк должны остаться фактически идентичными по полям
   `FoodCatalogItem` (включая неизвестную клетчатку).
4. `scripts/compare_usda_reviewed_catalogs.py` должен подтвердить
   `added_count=97`, `removed_count=0`, `changed_count=0`.
5. Должны быть пройдены pytest, Ruff, mypy и GitHub CI.
6. Перед записью в production: резервная копия `foods`, контроль состояния
   приложения, ограниченный импорт в уже существующую таблицу `foods`,
   повторный импорт с `created=0` и проверка публичного поиска.
   Личные дневники и пользовательские продукты не изменяются.

Начальное измерение охвата именно **проверенных USDA продуктов**, не всей
USDA и не произвольных чужих баз: v2 **118** -> v3 **215** (+97, +82,2%).
Это ограниченное покрытие, не универсальный российский каталог.

## Воспроизводимая процедура без автопубликации

Операции выполняются в доверенном backend окружении YFC с
`USDA_FDC_API_KEY` и отдельным `USDA_FDC_PROXY_URL`, исключительно
серверная среда, **секреты в консоль, JSON, Git не выводить**.

```bash
# Создать проверенный снимок. НЕ выполняет запись в БД.
python scripts/export_usda_reviewed_catalog.py --output .artifacts/usda_reviewed_v3.json

# Сравнить с последним опубликованным снимком; код возврата 2 означает
# изменения старых значений/удаления: запрещён автоматический импорт.
python scripts/compare_usda_reviewed_catalogs.py \
  .artifacts/usda_reviewed_v2.json .artifacts/usda_reviewed_v3.json \
  --output .artifacts/usda_v2_to_v3_diff.json

# Только после приёмки исходных данных и бэкапа:
python scripts/import_food_catalog.py .artifacts/usda_reviewed_v3.json --dry-run
python scripts/import_food_catalog.py .artifacts/usda_reviewed_v3.json
```

Периодическая актуализация: **раз в квартал** создавать новый снимок
официальных FDC ID, запускать сравнение с последним утверждённым, сохранять
версию набора и результаты проверки отдельно от логов приложения. **Никаких
автоматических обновлений боевой БД без подтверждения качества.** При изменении
описаний или пищевой ценности требуется новый review и версия карты (v4...),
а при недоступности USDA - не заменять старые данные нулями или пустым набором.

В будущих итерациях этого Issue предусмотреть проверенные позиции из
`Foundation` и `SR Legacy` только после реальной проверки структуры
нутриентов, единиц, лицензии и русских названий. Они пока не включены в v3,
и задача остаётся открытой до выполнения оставшегося объёма.
