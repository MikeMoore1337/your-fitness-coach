# Медиафайлы руководств по упражнениям

## Текущий состав

Медиафайлы руководств поставляются вместе с приложением. Во время работы не требуются CDN,
платный API или удалённый источник. Активный schema-3 manifest содержит 206 canonical
упражнений, 334 локальных Gym visual assets, 167 approved animations и 39 blocked entries;
общий размер файлов — 18 137 868 байт.

- для 167 упражнений используется по одной проверенной анимации и локальному poster;
- для 39 упражнений media намеренно отсутствует до появления source-backed материала;
- static-only и remote runtime assets отсутствуют;
- точный source identity, license, dimensions и SHA-256 находятся в
  `backend/assets/exercise-guides/manifest.json`.

## Выбор формата

Для approved entries используется animation-first Gym visual asset с локальным poster;
рендеринг сохраняет `contain` и не обрезает человека или оборудование. Для blocked entries
показывается компактный placeholder без искусственно сгенерированного media. Video, AI
generation и неизвестные remote sources не входят в active production contract.

## Контракт во время работы

`exercise_guide_metadata.media_reference` остаётся стабильной ссылкой, заданной предметной
областью упражнений. Факты о конкретных файлах хранятся в локальном манифесте, а метаданные
задачи 23 остаются источником истины для происхождения руководства. `ExerciseGuide.media[]`
возвращает:

- `type`, `url`, статический `poster`, фазу, альтернативный текст и стабильный `sort_order`;
- исходные `width` и `height`, чтобы заранее резервировать место, а также `byte_size` для
  контроля состава файлов;
- название и URL источника, название и URL лицензии для каждого элемента.

Для динамических силовых упражнений пользовательские подписи — `Фаза усилия` и `Фаза возврата`.
Легенда один раз связывает их с профессиональными терминами: концентрическая и эксцентрическая
фазы соответственно. Статичный кадр сам по себе не показывает изменение длины мышцы, поэтому
подпись описывает движение, которое **завершилось** в показанном положении. Направление проверено
отдельно для каждой пары по видимым конечным положениям и исходной инструкции упражнения; файл
не получает фазу автоматически из-за суффикса `start` или `active`. В API динамическая пара
упорядочена как фаза усилия, затем фаза возврата.

Для статических, циклических и многоэтапных движений используются нейтральные подписи подготовки,
удержания, положений цикла или последовательности. Это принципиально: концентрическая и
эксцентрическая классификация относится к действию конкретной мышцы, а не безусловно ко всему
упражнению. Такое ограничение терминов разобрано в публикации
[Concentric and Eccentric: Muscle Contraction or Exercise?](https://pmc.ncbi.nlm.nih.gov/articles/PMC3796841/).
Среднее преимущество максимальной эксцентрической силы около 40% получено преимущественно на
изокинетических измерениях и существенно зависит от скорости и упражнения
([метаанализ 335 исследований](https://pubmed.ncbi.nlm.nih.gov/37129779/)); поэтому интерфейс не
переносит это число на каждое упражнение и не обещает отдельного преимущества для роста мышц.

Устаревший массив `images[]` формируется из того же списка для обратной совместимости и не
является отдельным реестром.

Frontend запрашивает руководство только после того, как пользователь его открыл. Для медиа
используются нативные `loading="lazy"`, `decoding="async"`, исходные размеры, сохранённое
соотношение сторон и `object-fit: contain`. При ошибке загрузки остаётся доступный резервный
блок нужного размера, а текст техники не пропадает. Увеличение при наведении отключается при
настройке уменьшения движения.

Файлы упражнений отдаются через существующий same-origin mount `StaticFiles` с ETag, кэшем на
30 дней и однодневным `stale-while-revalidate`. Имена стабильны и не содержат хеш содержимого,
поэтому директива `immutable` намеренно не используется.

## Воспроизводимый процесс

Текущий production manifest имеет schema v3 и фиксирует только проверенный Gym visual
source. Для проверки каталога выполните:

```powershell
.\.venv\Scripts\python.exe scripts\validate_exercise_catalog.py
```

Исторический `scripts/build_exercise_guide_media_manifest.py` выведен из эксплуатации:
он целился в schema v2 и не является producer для активного manifest.json. Скрипт намеренно
завершается с ошибкой, чтобы не допустить перезапись schema v3 и неподтверждённого media.
Новые источники не добавляются этим task; изменение production manifest требует отдельного
owner-approved media stage и явной проверки provenance.
