# I3 — растительные продукты и болезненность: редакционный черновик

**Связано:** [Hermes #558](https://github.com/MikeMoore1337/hermes/issues/558), [научная проверка #317](https://github.com/MikeMoore1337/hermes/issues/317). Дата подготовки: 25.10.2026.

**Единственный источник текста:** [структурированный черновик](../../backend/tests/fixtures/i3_plant_recovery_editorial_draft.json), поле `body_sections`. В нём содержится полная будущая статья на русском языке, три source-bound утверждения и матрица источников.

- **Проверено технически:** соответствие `HermesWebArticleProposal`, как только пройдут тесты `backend/tests/test_i3_plant_recovery_editorial_draft.py`; разрешённые поля, HTTPS-источники, минимальное число источников, полное покрытие claims.
- **Не утверждено:** ни один claim не имеет `review_status=verified`. Достоверность указана `limited`, `domain_reviewer=null`. Существующие правила YFC оставляют `claim_source_matrix_not_fully_verified` и `domain_reviewer_required` как блокеры.
- **Публикация запрещена:** файл **не** `HermesWebArticleIntakeRequest`: нет `candidate_id`, nonce, idempotency key, signature, provenance, URL назначения, команды для POST или credentials. Его нельзя передавать в API как готовый запрос.
- **Не подменять независимого учёного:** присланные владельцем рецензии содержат общий HOLD; экспертная подпись для конкретного текста не подтверждена. YFC автор/редактор Organization — условные метаданные черновика, не подпись действительного редактора.
- **Никаких новых работ по переоценке всего научного пакета:** достаточно сохранить ограничения, не добавлять дозы, медицинские назначения, обещания работоспособности или рекламные CTA.
- **Ограничения лицензий:** текст составлен заново, без копирования таблиц, изображений и длинных фрагментов исследований; источники содержат первичные URL. Права на сторонние медиа, если они будут предложены позже, рассматриваются отдельно.

## Дальнейшее действие по реально полученным согласованиям

1. Идентифицированный научный специалист подтверждает **конкретный текст** и ограничения; отсутствие такого решения сохраняет `HOLD`.
2. Редактор YFC проверяет статьи, матрицу источников, чувствительную тематику и версии источников. Никакого `verified` по самим данным Hermes.
3. Владелец отдельно разрешает конкретную передачу. Только после этого используются существующий кандидат в БД YFC, точный `candidate_id`, действующий `hermes-web-article-intake-v1`, согласованные provenance и штатный HMAC-контур.
4. Допустимый intake создаёт **только draft**; наличие `accepted` не означает `approved` или `published`. Публикация через существующий отдельный owner/editor маршрут.

**Запрещено** создать фиктивного reviewer, подставить placeholder подпись/ORCID, обойти научный preflight, менять TDEE/БЖУ или отправлять данные в Second Brain.

Техническая доставка этих fixture/docs/tests в GitHub ≠ доставка живого I3 в редакционный сервис и не создаёт публичную статью.
