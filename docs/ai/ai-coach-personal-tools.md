# AI Coach: персональные read-only tools (Task 89)

Task 89 добавляет отдельный, выключенный по умолчанию маршрут персонального AI Coach.
Он объясняет ограниченную сводку уже рассчитанных сервером фактов. Экран прогресса,
тренировок или питания остаётся источником фактов; ценность AI Coach — в коротком
естественно-языковом объяснении выбранной сводки и её ограничений, а не в замене
детерминированного отчёта.

## Разрешённые tools

| Tool | Канонический источник | Период | Результат и fallback |
| --- | --- | --- | --- |
| `get_progress_summary` | `build_progress_summary` | 7/30/90 дней | Сводка тренировок, кардио, питания, замеров и sufficiency; экран `/progress` |
| `get_recent_training_summary` | `build_training_analytics` | 7/30/90 дней | Ограниченные агрегаты тренировок и RIR без сессий/заметок; экран `/progress` |
| `get_nutrition_summary` | `build_nutrition_report` | 7/30/90 дней | Агрегаты питания, история целей и гидратация без дневного raw payload; экран `/nutrition` |

`explain_recommendation` пока не включён: в текущем контракте нет безопасного
канонического идентификатора конкретной рекомендации и её версии. Добавлять tool
до появления такого источника означало бы разрешить AI Coach додумывать связь между
сводкой и рекомендацией.

Каждый tool принимает только server-selected current user и allowlist периода. В
контекст передаются стабильные значения, единицы, даты, sufficiency и limitations.
Идентификаторы аккаунта, Telegram/email, trainer/client data, raw diary, notes,
ORM-объекты и произвольные поля не передаются. Пропуск, incomplete и missing не
считаются нулём; отсутствие записанного значения не восстанавливается расчётом.

## Согласие и политика

Перед первым персональным вызовом пользователь отдельно включает согласие через:

- `GET /api/v1/ai-coach/consent`;
- `PUT /api/v1/ai-coach/consent` с `{ "enabled": true|false }`;
- `POST /api/v1/ai-coach/personal/generate`.

Согласие имеет версию `ai-coach-personal-v1`, scope
`personal_readonly_tools_v1`, источник `ai_coach_settings` и категории
`personal_progress`, `training_history`, `nutrition_summary`. Изменение версии,
scope или проверенной provider policy делает прежнее решение неактивным и требует
нового согласия. Отзыв прекращает новые вызовы, но запись решения сохраняется в
экспорте аккаунта.

Персональный provider route дополнительно требует отдельного runtime-переключателя
`AI_COACH_PERSONAL_ENABLED=true` и `AI_COACH_PERSONAL_DATA_POLICY=verified_personal_user`.
Это не включается автоматически вместе с generic AI Coach. При отсутствии настройки,
ключа, провайдерской policy или структурированного output система возвращает
контролируемый `unavailable`.

В provider уходит только текущая ограниченная структурированная сводка для выбранного
tool и пользовательский вопрос. Промпт, ответ и tool payload не сохраняются в БД;
в логах остаются только request metadata, outcome, tool name, latency, token/cost
metadata и безопасный error code. Экспорт содержит только историю согласия и не
содержит prompt/answer/context payload. Удаление аккаунта удаляет запись согласия.

## Ограничения безопасности

Маршрут аутентифицирует текущего пользователя на сервере при каждом вызове. Нет
параметра `user_id`, SQL, URL, query DSL, provider/model override, произвольного
периода или model-controlled tool loop. Tool выполняется один раз, provider получает
один bounded context, персональная генерация не повторяется автоматически. Ответ
проверяется по строгой JSON-схеме, разрешённым `ref_id`, русскому языку и блоклистам
медицинских назначений, секретов, prompt injection и изменений пользовательских
данных.

Personal tool evidence трактуется как недоверенные данные: пользовательский текст и
пользовательские названия упражнений не могут изменить policy, раскрыть prompt или
выдать чужие данные. При небезопасном содержимом provider не вызывается.

AI Coach не ставит диагнозы, не назначает лечение/добавки, не меняет программу,
цель, калории или расписание и не выдумывает калории кардио, wearable facts,
прогрессию или идеальные телесные показатели. При недостатке данных пользователь
получает `insufficient_data` и путь к исходному экрану.
