# Your Fitness Coach — Product V11 / Issue #821

Репозиторий: https://github.com/MikeMoore1337/your-fitness-coach

Issue: https://github.com/MikeMoore1337/your-fitness-coach/issues/821

Родительская задача: #814

**Задача: самостоятельно реализовать V11-06 — CI Efficiency, Determinism and Regression Truth.**

Цель — заметно уменьшить время GitHub Actions при сохранении полноценной проверки качества, безопасности и корректности приложения.

## Контекст

Product V11 активен. Задачи #815 и #819 закрыты.

Frontend-задача #818 имеет отдельный PR #1126, её производственный выпуск ожидает PostgreSQL gate #848.

Параллельно выполняются #816 и #851. Их файлы и область ответственности нельзя изменять без необходимости.

## Этап 1 — измерения

Проанализируй репозиторий, CI-скрипты и историю GitHub Actions.

Используй репрезентативные завершённые запуски, желательно не менее 15–30, если данные доступны.

Измерь:

- Полное время CI от запуска до окончательного результата.
- Длительность наиболее дорогих заданий.
- Распределение Python-тестов и frontend smoke по группам.
- Ожидание GitHub runner.
- Затраты на установку зависимостей, Docker-сборки и загрузку артефактов.
- Эффективность кеширования.
- Повторяющиеся операции.
- Подтверждённые нестабильные проверки.

Разделяй время очереди, фактическое время работы и суммарное процессорное время. Не используй неподтверждённые оценки как baseline.

## Этап 2 — реализация

Реализуй изменения с измеримой пользой:

1. Улучши балансировку тестовых групп при наличии доказанного перекоса.
2. Устрани действительно дублирующиеся этапы, только если их проверочное покрытие сохраняется.
3. Оптимизируй кеширование с проверкой его корректности.
4. Пересмотри избыточную последовательность независимых заданий.
5. Исправь подтверждённые причины нестабильности.
6. Проверь маршрутизацию задач по изменённым файлам.
7. Сохрани корректную работу агрегирующего `checks`, включая отрицательные сценарии отсутствующих, пропущенных и упавших обязательных проверок.

## Жёсткие ограничения

- Не удалять содержательные тесты ради скорости.
- Не ослаблять CodeQL, Trivy, dependency audit, secret scanning, provenance или защиту ветки.
- Не добавлять безусловные повторы, которые маскируют ошибки.
- Не вводить ложный зелёный CI из-за кеша или пропущенной проверки.
- Не восстанавливать controller.
- Не менять production deploy, PostgreSQL и приложение для выполнения этой задачи.
- Не изменять Dockerfile, SBOM и digest-pinning — ими занимается #851.
- Избегать конфликтов с PR #1122, #1126 и #1131.
- Не использовать платные сервисы или дополнительные платные GitHub runners.

## Приёмка

Измерь время CI до и после изменений. Используй сопоставимые условия, учитывай вариативность runner и кеша.

Если ускорение не подтверждено, не объявляй его достигнутым. Верни или доработай неэффективные изменения.

Добавь тесты контрактов для маршрутизации, агрегирования CI и сохранения обязательных проверок.

Создай отдельный PR и добейся прохождения обязательных GitHub Actions.

Слияние в `master` допускается только после проверки, что изменения действительно не инициируют небезопасный production deploy; при отсутствии доказательства оставь PR открытым. Gate #848 не обходить.

## Финальный отчёт

Укажи:

- BEFORE/AFTER полной длительности CI.
- Изменение времени самых дорогих заданий.
- Реальную экономию времени и её условия.
- Какие проверки сохранены.
- Какие риски устранены.
- Точный SHA, ссылку на PR, итоговый CI.
- Готовность к слиянию с отдельной оценкой release safety.

Не заканчивай работу после анализа: реализуй обоснованные улучшения и проверь их на реальных GitHub Actions.
