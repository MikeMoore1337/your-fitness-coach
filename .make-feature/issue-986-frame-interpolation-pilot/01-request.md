# Your Fitness Coach — AI Frame Interpolation: повышение плавности анимаций упражнений

**Репозиторий:** https://github.com/MikeMoore1337/your-fitness-coach
**Основная задача:** https://github.com/MikeMoore1337/your-fitness-coach/issues/986
**Связанные PR:** #1094, #1109, #1070
**Основная ветка:** `master`
**Приоритет:** P2
**Оборудование:** NVIDIA RTX 4060 Ti
**Статус:** Owner-approved research and implementation pilot

## Цель

Самостоятельно реализуй и проведи полноценный эксперимент по повышению плавности AI-анимаций упражнений в Your Fitness Coach с использованием нейросетевой интерполяции кадров.

Сейчас AI-pipeline увеличивает исходные GymVisual GIF с 180×180 до 720×720 с помощью RealESRGAN_x4plus, но сохраняет исходное количество кадров.

По данным manifest PR #1109:

- 90 новых AI-upscaled анимаций.
- 83 из 90 имеют эффективную частоту 4 FPS.
- 77 упражнений уже имеют нативные HD-анимации.
- 4 AI-пилота реализованы ранее.
- 35 упражнений пока не имеют подтверждённого подходящего медиа.

**Главная цель — получить более плавное движение без изменения правильной техники упражнения.**

Не ограничивайся исследованием: реализуй рабочий воспроизводимый pipeline, выполни реальную GPU-обработку, сравни результаты и подготовь полноценный Draft PR для визуальной приёмки.

## 2. Выбор технологии

Основной кандидат — RIFE.

Официальные источники:

- https://github.com/hzwer/ECCV2022-RIFE
- https://github.com/nihui/rife-ncnn-vulkan

Предпочтительно использовать GPU-ускорение на RTX 4060 Ti.

Исследуй:

- Доступную версию и модели RIFE.
- Совместимость с 720×720.
- Возможность интерполяции в произвольный временной момент.
- Скорость обработки.
- Потребление VRAM.
- Лицензию реализации и используемых моделей.
- Воспроизводимость на Windows.

Важно: 12 FPS из исходных 4 FPS требуют корректного создания промежуточных кадров в точках 1/3 и 2/3 каждого интервала. Если выбранная реализация RIFE умеет только midpoint-интерполяцию, не выдавай простое дублирование кадров или некорректное пересэмплирование за настоящую 3× интерполяцию.

При необходимости используй другую официальную реализацию RIFE, поддерживающую произвольный timestep.

Не устанавливай тяжёлые зависимости в основной Python environment YFC. Используй изолированный инструмент или portable GPU runtime.

## 3. Подготовка экспериментального набора

Выбери 8 разных упражнений из 90 новых AI-upscaled анимаций.

Предварительные кандидаты:

1. `ab-wheel` — движение корпуса и рук.
2. `leg-press` — движение ног и тренажёра.
3. `romanian-deadlift` — движение тазобедренного сустава и грифа.
4. `kettlebell-swing` — быстрая траектория снаряда.
5. `treadmill-walk` — циклическая ходьба.
6. `assault-bike` — одновременное движение рук и ног.
7. `turkish-get-up` — сложное многофазное движение.
8. `dragon-flag` — длинное перемещение корпуса.

Перед обработкой проверь, что эти упражнения действительно присутствуют в нужном наборе и не имеют более приоритетного нативного HD-видео.

Если кандидат не подходит, замени его упражнением с аналогичной сложностью и зафиксируй причину.

Набор должен включать простые, сложные, быстрые, медленные и циклические движения.

## 4. Реализуй Frame Interpolation Pipeline

Создай отдельный воспроизводимый инструмент для интерполяции.

Вход:

- Исходный approved AI-upscaled MP4 либо сохранённые несжатые upscale-кадры.
- Canonical exercise ID.
- Provenance и SHA исходного материала.
- Реальные временные метки исходных кадров.
- Целевой FPS.
- Путь к модели RIFE.

Предпочитай несжатые 720×720 upscale-кадры, если они доступны, чтобы избежать повторных потерь качества из-за H.264.

Результат:

- Новые промежуточные кадры.
- H.264 MP4 720×720.
- `yuv420p`.
- Без аудио.
- С неизменной общей продолжительностью движения.
- С корректными PTS и кадровой последовательностью.
- С reproducible processing report.

Поддержи целевые режимы:

- 8 FPS.
- 12 FPS.
- 16 FPS.

Для каждого режима должны генерироваться настоящие новые промежуточные изображения, а не просто дубли исходных кадров.

Учитывай исходные GIF с нестандартными длительностями кадров и эффективной частотой, отличной от 4 FPS.

Не замедляй и не ускоряй упражнение ради увеличения FPS.

Сохраняй исходные кадры как опорные точки движения с максимально точным временным соответствием.

Отдельно обрабатывай переход между последним и первым кадром зацикленной анимации. Если корректный бесшовный переход не подтверждён, сохраняй исходную семантику цикла без генерации вымышленных фаз.

## 5. Выполни реальную GPU-обработку

Используй RTX 4060 Ti для обработки экспериментального набора.

Для каждого из восьми упражнений создай:

- Baseline AI-upscaled 720×720.
- RIFE 8 FPS.
- RIFE 12 FPS.
- RIFE 16 FPS.

Ожидается до 24 новых экспериментальных MP4.

Pipeline должен:

- Поддерживать resume.
- Пропускать уже корректно обработанные результаты.
- Проверять SHA входа и выхода.
- Записывать версию модели и runtime.
- Не уничтожать промежуточные результаты после ошибки.
- Давать понятные сообщения об ошибках.
- Позволять повторить эксперимент.

Не используй платные облачные GPU без разрешения владельца.

Если доступ к RTX 4060 Ti отсутствует, проверь доступные локальные альтернативы и честно обозначь ограничение. Не подменяй реальные результаты синтетическими примерами.

## 6. Контроль качества

Для каждого экспериментального MP4 проверь:

**Техническая корректность**

- H.264 / yuv420p / 720×720.
- Нет звуковой дорожки.
- Фактический FPS соответствует целевому.
- PTS монотонны.
- Нет нарушений длительности и дрейфа тайминга.
- Видео декодируется полностью.
- Нет повреждённых или чёрных кадров.
- Нет неожиданных дубликатов, используемых вместо интерполяции.
- Количество кадров соответствует выбранной временной сетке.
- Исходные файлы не изменены.

**Визуальная корректность**

- Положение суставов.
- Форма и длина конечностей.
- Направление движения.
- Положение рук и ног.
- Хват и контакт с оборудованием.
- Траектория грифа, гантели, гири или рукоятки.
- Отсутствие пропадающих объектов.
- Отсутствие «резиновой» анатомии.
- Отсутствие ghosting и сильного мерцания.
- Корректность перехода между концом и началом цикла.

Особенно внимательно проверь `kettlebell-swing`, `turkish-get-up` и `dragon-flag`.

Автоматические motion metrics не доказывают правильность техники. Не присваивай `VERIFIED` только на основании успешного декодирования или числового качества.

## 7. Сравнение качества

Подготовь локальную HTML-галерею.

Для каждого упражнения покажи варианты рядом:

| Original GIF | AI-upscale | RIFE 8 | RIFE 12 | RIFE 16 |
|---|---|---|---|---|

Требования:

- Синхронное начало воспроизведения.
- Одинаковая длительность.
- Зацикленное движение.
- Возможность поставить на паузу.
- Возможность покадрового сравнения.
- Просмотр в реальном масштабе 720×720.
- Просмотр в типичном мобильном размере.
- Возможность переключать варианты.
- Отображение размера файла и фактического FPS.

Дополнительно сформируй contact sheets для первой, средней и последней фаз упражнения и подозрительных участков движения.

Галерея должна работать с реальными локальными результатами.

Не создавай фальшивые BEFORE/AFTER изображения.

## 8. Производительность и стоимость доставки

Для каждого варианта измерь:

- Размер MP4.
- Увеличение размера относительно baseline.
- Время GPU-обработки.
- Пиковое использование памяти, если измерение доступно.
- Производительность декодирования в Chromium.
- Производительность в Playwright WebKit.
- Корректность воспроизведения с `muted autoplay loop playsInline`.
- Поведение при reduced-motion.
- Fallback при отказе загрузки.

Сравни реальную визуальную пользу с увеличением размера видео.

Не выбирай 16 FPS автоматически, если 12 FPS практически не уступает по качеству или более высокая частота создаёт артефакты.

## 9. Автоматическая оценка

Введи статусы:

- `PASS` — технические проверки и визуальная оценка выполнены.
- `REVIEW` — технически корректно, но качество требует проверки.
- `REJECTED` — обнаружено искажение или регрессия.

Допускается отдельный статус `TECHNICAL_PASS_VISUAL_PENDING`, если автоматические проверки завершены, а ручная визуальная приёмка ещё не состоялась.

Подготовь отчёт по каждому упражнению с объективными метриками, ссылками на файлы и явными причинами отклонения.

Никакой автоматической публикации результатов со статусом `REVIEW`, `REJECTED` или `VISUAL_PENDING`.

## 10. Выбор оптимального FPS

После обработки сравни 8, 12 и 16 FPS.

Приоритеты:

1. Правильная техника упражнения.
2. Отсутствие AI-артефактов.
3. Плавность движения.
4. Отсутствие рывка при повторении цикла.
5. Размер файла и мобильная производительность.

**12 FPS — основной кандидат, но не заранее утверждённый победитель.**

Если для одного упражнения лучше 8 FPS, а для другого 16 FPS, допускается разный выбор в зависимости от сложности движения.

Подготовь аргументированную рекомендацию для каждого из восьми упражнений.

## 11. Подготовка масштабирования на 90 анимаций

Если пилот технически успешен, реализуй возможность пакетной обработки оставшихся AI-анимаций.

Но не запускай автоматическую замену всех production assets без визуальной приёмки пилота.

Pipeline должен поддерживать:

- Выбор упражнений по canonical ID.
- Обработку партиями.
- Возобновление обработки.
- Ограничение GPU-нагрузки.
- Проверку source SHA.
- Проверку model/version.
- Manifest validation.
- Отчёт о пропущенных и отклонённых файлах.
- Возможность индивидуального выбора FPS.
- Сохранение текущего AI-upscaled MP4 как fallback.
- Сохранение исходного GIF как последнего fallback.

Приоритет медиа после будущего одобрения:

1. Verified native HD.
2. Verified AI-upscaled + frame-interpolated video.
3. Current approved AI-upscaled video.
4. Original GIF.

Не заменяй 77 нативных HD-анимаций.

## 12. Ограничения и GitHub workflow

Работай независимо от #1094 и #1109.

1. Проверь текущий статус этих PR.
2. Создай отдельную Issue для Frame Interpolation.
3. Создай отдельную ветку и Draft PR для pipeline, тестов и отчёта.
4. Не включай 24 экспериментальных видео в production manifest до визуальной приёмки.
5. Не коммить большие модели RIFE, временные кадры, GPU runtime и экспериментальные binary assets в основной PR.
6. Сохрани результаты в `.artifacts` или другом игнорируемом каталоге.
7. Предоставь галерею и отчёты в доступном владельцу виде: локальные пути плюс, по возможности, GitHub Actions artifacts.
8. При необходимости после принятия пилота создай отдельный asset PR.

Не выполняй merge или production deploy без разрешения владельца.

Не задерживай существующий выпуск #1094/#1109 из-за эксперимента с интерполяцией.

## 13. Тесты и CI

Добавь тесты на:

- Исходные тайминги.
- Интерполяцию до 8/12/16 FPS.
- Неравномерную длительность GIF-кадров.
- Циклическую анимацию.
- Точность PTS.
- Неправильный source SHA.
- Несовместимую версию модели.
- Повреждённый выходной файл.
- Повторный запуск обработки.
- Возобновление после ошибки.
- Защиту original GIF и baseline MP4 от перезаписи.
- Неправильную привязку canonical ID.
- Исключение native HD из пакетной обработки.

Проверь Ruff, pytest, pre-commit, каталожные валидаторы, подходящие frontend-тесты и обязательный CI.

Тяжёлые GPU inference-тесты не должны автоматически выполняться при каждом обычном CI, если это требует недоступного оборудования. Для них предусмотрите отдельный воспроизводимый запуск.

## 14. Definition of Done

Пилот считается технически завершённым, если:

- Реализован работающий RIFE pipeline.
- Обработаны 8 реальных упражнений.
- Для каждого сформированы варианты 8/12/16 FPS.
- Продолжительность упражнений сохранена.
- Новые кадры действительно интерполированы.
- Технические QC-проверки пройдены.
- Проведены сравнительные browser-проверки.
- Подготовлена интерактивная галерея.
- Проведено измерение размера и производительности.
- Для каждого упражнения предложен оптимальный вариант.
- Реализована подготовка к пакетной обработке остальных 90 анимаций.
- Текущие GIF и MP4 не изменены.
- Открыт Draft PR с успешным CI.
- Issue содержит доказательства и ссылки на артефакты.

Ручное подтверждение точности техники владельцем остаётся отдельным acceptance gate.
