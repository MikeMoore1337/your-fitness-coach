После официальной активации Product V11 разрешаю самостоятельную реализацию #819: аудит, доказательные исправления тестов, создание отдельной ветки и Draft PR.

Merge и production deploy требуют отдельного разрешения.

## Цель

Сделать существующий набор автотестов YFC более надёжным, детерминированным и способным обнаруживать реальные регрессии.

Критерий успеха — не максимальный процент покрытия и не количество новых тестов, а проверяемое улучшение качества регрессионной защиты.

## 1. Актуальный baseline

Изучи:
- Issue #819;
- результаты #815;
- merged baseline-отчёт `product-v11-00-baseline-2026-10-18.md`;
- текущий master;
- историю CI и соответствующие тестовые framework.

Зафиксированный baseline:
- 155 frontend unit-test files;
- 949 frontend unit tests passed;
- Python suite не был полностью воспроизведён локально на Windows;
- scheduled mobile regression имела failure в Firefox/WebKit;
- Allure publication имела отдельный SSH timeout;
- CI на документационном PR не является доказательством полной регрессии.

Все числа перепроверь на актуальном HEAD.

## 2. Аудит тестов

Исследуй backend pytest, frontend Vitest, Playwright, интеграционные проверки PostgreSQL и GitHub Actions.

Особое внимание:

- assertions, которые проходят при неправильном поведении;
- тесты, проверяющие исключительно mock;
- устаревшие fixtures;
- необоснованные skip/xfail;
- чувствительность к времени, порядку запуска и состоянию окружения;
- проверки authorization и tenant isolation;
- database transaction boundaries;
- идемпотентность мутаций;
- concurrency, optimistic conflicts и retries;
- offline/reconnect/resume;
- чувствительные данные, export/delete и privacy boundaries;
- русская локализация, исключения для брендов и технических терминов.

Не называй тест flaky без воспроизводимого сбоя либо достоверной истории CI.

## 3. Приоритетные пользовательские сценарии

Проверь покрытие:

1. Authentication и session startup.
2. Today.
3. Active Workout, rest timer и восстановление после offline.
4. Nutrition targets, planning, diary и history.
5. Programs, exercise encyclopedia.
6. Coach OS и доступ тренера к клиентам.
7. Export/delete, RBAC и приватность.
8. PWA/TMA resume и reconnect.
9. Миграции и legacy data.

Отдельные задачи #1091, #1072 и #986 не должны поглощаться этим PR. Допускаются целевые regression tests, но не широкое изменение их продуктовой логики.

## 4. Реализация

Не останавливайся на аудиторском отчёте.

Для подтверждённых проблем:

- усили слабые assertions;
- добавь необходимые negative/boundary tests;
- исправь неправильные fixtures;
- добавь детерминированные auth/RBAC regression tests;
- добавь проверки идемпотентности и конфликтов там, где существует доказанный пробел;
- устрани воспроизводимые flaky причины в рамках тестового кода;
- проверь, что ошибочное поведение действительно приводит к красному тесту.

При обнаружении дефекта production-кода создай отдельную Bug Issue с воспроизведением. Не внедряй крупные продуктовые исправления в #819 без согласованного scope.
